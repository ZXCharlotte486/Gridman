# W18: 输出四维自检（交付前验证）

**触发场景：** 古立特做完任何**专业产出**后、交付给用户**之前**，自动跑一遍——不分领域：审计底稿、税务测算、估值模型、IPO尽调清单、ESG报告、政府会计分录、报表分析、账龄、函证清单……凡是"有数、有判断、要交付"的，都先过这道关。
**适用判断：** 凡含数据、判断、引用、口径换算的专业产出 → 必走。纯概念问答、一句话定义、闲聊 → 不必走。
**依赖工具：** 无强制依赖（纯自检流程）；需复算时可借任意计算工具。
**依赖知识：** 对应产出所属领域模块（准则维度回查）+ SKILL.md「搜索决策流程」（引用维度）。

> 定位：Anthropic/Perplexity 认证——验证类能力对输出质量提升最可量化，是古立特此前最大缺口。本工作流是 SKILL.md「交付前复核总闸」**维度A（产出正确性）**的完整展开——把原"只管算术勾稽"的报告自复核，升级为覆盖**整个财税大方向**的四维通用自检（维度B 多视角、维度C 对抗者由总闸在 SKILL.md 直接执行）。
> 来源：Anthropic《Lessons from building Claude Code》Product-verification 类 + CSA 1320/1520 + 古立特铁律
> 性质：实操+判断

这是古立特"破坏的力量用在自己身上"——能找出别人产出里的雷，先找出自己刚做完的产出里的雷。

## 四个维度（通用原则，不是某类报表的固定清单）

> 四维是**跨财税全领域的通用自检原则**。下面每维的"举例"只是帮助理解，不是穷举——遇到任何产出，把该维原则套到当前产出上自检即可。

### 维度1·勾稽（一致性与平衡）

**原则**：产出里**相互依存的数据必须自洽**——该相等的相等、该加总的加总对、该平衡的平衡。

- 举例（不限于）：报表三表勾稽、TB 借贷平衡、未审+调整=审定、账龄各桶之和=期末余额、估值各步加总=企业价值、税额=税基×税率、变动额/率/结构比算式、合计=明细之和。
- 自检动作：把产出里所有"本该对得上"的关系挑出来，逐一复算。
- 发现差异：先自修（重新加总）；自修不了 → 红字标出具体差异项和金额，**绝不假装对上了**（铁律2）。

### 维度2·依据正确（准则/标准/口径）

**原则**：产出里每个判断和处理，用的**规则/标准是现行有效、且适用本场景**的。

- 举例（不限于）：会计准则、税法税率/扣除比例、审计准则、监管规则适用指引、评估准则、ESG披露框架——版本现行、没引用已废止规则、适用前提在本case确实成立。
- 自检动作：每条关键判断回问"依据是什么、现在还有效吗、这个场景真的适用吗"。
- 发现问题：改用正确依据重做；拿不准 → 标"此处依据适用需复核"，不硬下结论（铁律3）。

### 维度3·口径一致（同一概念全篇一义）

**原则**：同一个指标/术语/单位/时间口径，**全篇保持一个意思**，与数据来源口径一致。

- 举例（不限于）：收入含税/不含税前后统一、合并范围一致、单位（元/万元/亿元）不混、时点vs时段不混、本期vs累计不混、与来源（客户TB/年报）口径一致。
- 自检动作：挑出反复出现的关键指标，确认每处定义、单位、时间范围一致。
- 发现问题：统一口径并标注换算依据；来源与结论口径不同时显式说明桥接。

### 维度4·引用核实（出处可溯）

**原则**：产出里引用的**文号/数字/条款，要么查证过、要么标"待核实"，绝不编造**（铁律1）。

- 举例（不限于）：法规文号、准则条款编号、税率/限额/阈值、监管案例编号——有出处才引，引用即注明。
- 自检动作：把产出里所有"看起来精确"的引用挑出来，逐一确认来源。
- 发现问题：按「搜索决策流程」联网查证（同一事实最多2个独立源）；仍查不到 → 如实标注边界，不用"大概/应该是"补。

## 关键判断

| 维度 | 一句话标准 | 通用范围 | 对应铁律 |
|---|---|---|---|
| 勾稽 | 相互依存的数都自洽、没假装平 | 任何含数产出 | 铁律2 |
| 依据 | 用的是现行有效、且本场景适用的规则 | 会计/税/审/监管/评估/ESG… | 铁律1/3 |
| 口径 | 同一个词全篇一个意思 | 任何含指标产出 | —— |
| 引用 | 文号数字都查过、查不到就说查不到 | 任何含引用产出 | 铁律1 |

## 输出

- 四维全过 → 在交付物末尾盖"✅ 已四维自检（勾稽/依据/口径/引用）"标签，用户不必替古立特复核。
- 任一维有未决问题 → 用红字/⚠️ 标出具体问题点 + 影响，**带着标注交付**，不藏不掩。
- 自检中发现的真实判断错误 → 按「踩坑记录规则」追加到 `gridman-mind/feedback/gotchas.md`（飞轮闭环）。

## 验证清单

> 交付任何专业产出前逐条核对。

- [ ] 维度1 勾稽：相互依存的数据已复算、平衡/合计无误
- [ ] 维度2 依据：所用规则现行有效、本场景适用、时效已确认
- [ ] 维度3 口径：指标/单位/时间/来源口径全篇一致
- [ ] 维度4 引用：文号数字已查证或标"待核实"，已注明出处
- [ ] 发现的差异已自修或红字标出，无"假装通过"
- [ ] 发现的真实判断错误已记入 feedback/gotchas.md
