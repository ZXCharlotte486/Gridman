# 工作流编写规范

> 这里不是工作流文件本身，而是告诉你**怎么写**工作流文件。
>
> 当你需要为某个财税任务创建一个 step-by-step 指引时，按此规范新建 `.md` 文件。


## 定位

Workflow 属于 `gridman-skill` 的任务编排层，负责声明判断点、绑定 `references/knowledge/` 的专业依据、组织业务步骤与能力需求，并定义异常处理和验收标准。Workflow 不独立创造法规事实或专业结论；古立特不内置、不分发、不维护 MCP Server，运行时从宿主原生能力、宿主已配置的 MCP 工具或本机 CLI 中寻找实现。

具体 Workflow 只有在对应 `.md` 文件实际存在，并经领域路由后的子树动态发现确认与任务、输入条件匹配时才能加载。目录中没有匹配文件时，必须使用相关 knowledge 与 `operations/routing_flow.md` 的通用执行流程诚实降级，不得声称已进入或执行不存在的 Workflow。新增单个 Workflow 通常无需在 `operations/routing_index.md` 逐文件登记。

## 文件规范

每个工作流文件以 frontmatter 开头：

```yaml
---
workflow: 工作流名称
version: 1.0
profession: 审计 / 财务 / 税务 / 投行 / 分析
output_type: 底稿 / 报告 / 数据 / 建议
risk_level: low / medium / high
required_inputs:
  - 必要材料
required_capabilities:
  - filesystem.read
optional_capabilities:
  - script.execute
external_write: false
mind_write: true
---
```

正文结构：

```markdown
# {工作流名称}

## 触发条件
（什么用户话术触发此 Workflow）

## 前置条件
（必要材料、业务口径、缺失材料时如何处理）

## 专业知识绑定
（需要读取哪些 knowledge 文件或章节）

## 执行步骤
### 步骤1：xxx
- 业务动作与判断
- 输入与输出
- 所需抽象能力
- 失败或缺失时的降级

## 工具选择与授权
（发现并验证宿主原生能力、宿主 MCP 或 CLI；外部写入、上传、覆盖、删除、批量修改前先确认）

## 异常处理
（格式、路径、连接、权限、重复写入等异常的处理）

## 复核检查点
（统一复核总闸 + 本 Workflow 专属业务验收）

## 产出物
（文件格式、命名、归档位置和验收标准）

## Mind 写入规则
（项目状态、输出、重要判断和真实错误分别写到哪里）
```

## 验收标准必须可否证

每个步骤和「复核检查点」里的验收条款，必须写成**有可能失败**的检查。写完一条验收后自问：存在什么情况会让它不通过？答不出来，这条就是无效验收。

典型的无效写法：

| 无效验收 | 为什么无效 | 改法 |
|---|---|---|
| 聚合后凭证数等于唯一键数量 | 聚合动作的自洽性，任何键定义都通过 | 检查结构分布是否落入异常信号区间 |
| 计算结果与公式一致 | 同一段计算自证，算错也一致 | 与独立来源（控制数、报表、外部证据）交叉核对 |
| 文件已生成且可读 | 只是技术成功，不涉业务 | 核对行数、控制总数、期间与口径 |
| 已按准则处理 | 无判定主体，无从核查 | 指明具体条款号与判断依据，可回溯 |

合格验收至少满足一条：与**独立来源**勾稽（不是自己的中间结果）、或给出**具体阈值/区间**、或要求**可回钻到原始记录**。

同时注意：上游步骤的假设不会被下游的总额勾稽发现。若某步依赖一项关键假设（主键定义、期间口径、币种、口径归一规则），必须在该步骤内部安排主动验证，不能指望后续平衡检查兜住——**总额勾稽对聚合口径错误不敏感**。

## 注意事项

- Workflow 是 **业务编排协议**，不是与某个工具绑定的编程脚本。
- 使用抽象能力类别描述需求，不把具体 MCP 名称或 CLI 命令写成唯一实现。
- 执行时依次发现并验证宿主原生能力、宿主 MCP 与本机 CLI；`current.md` 的历史能力记录只能作为提示，不能替代实时验证。
- 工具调用成功不等于业务完成，必须通过本 Workflow 专属验收和统一复核总闸。
- 涉及上传、外部写入、覆盖、删除或批量修改时，执行前必须取得用户确认。
- 不向未知第三方传输财税数据。
- 能力不足时退回「知识指引模式」，提供方法、公式、模板和检查清单，并明确哪些操作没有实际完成。
