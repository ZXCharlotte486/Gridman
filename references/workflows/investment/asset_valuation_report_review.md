# 资产评估报告审核

对一份已出具的资产评估报告做技术合理性复核：识别报告类型 → 提取基本信息与关键参数 → 分维度审核 → 三方交叉验证 → QSC 评分 → 出审核结论与报告。只审核报告自身技术合理性，不重做评估，不做报告外业务判断。

## 触发条件

- 用户提供资产评估报告并要求"审核/复核/挑问题/评分/看看评估报告有没有问题"。
- 用户在尽调、并购、IPO、国资交易中需要判断某份评估报告是否可靠。
- 关键词：资产评估报告审核、估值参数审核、WACC 审核、评估假设审核、评估合规性、QSC 评分、商誉减值测试报告复核、数据资产/碳资产评估审核。

不触发：用户要求"做一份评估/估值建模"（那是评估/估值任务，走 investment.md 知识与通用流程），或只问评估方法概念（纯知识问答）。

## 前置条件

- 必须先拿到报告正文。报告为 PDF/图片时需要文本提取能力；为 Word/文本时可直接读取。
- 有 Excel 底稿（收益法申报表、成本法明细表）时，交叉验证维度 D7 才能完整执行；无底稿时 D7 降级为"仅报告内部一致性"，并在报告中说明未做底稿比对。
- 缺报告类型时，先从报告正文的评估对象/价值类型判定；仍无法判定则询问用户，不臆断。

## 专业知识绑定

- 审核维度、量化阈值、检查点、QSC 评分、审核结论判定、AI 能力边界 → `references/knowledge/investment/asset_valuation_review.md`（主依据）
- 评估方法选择、法定必须评估情形、评估与会计/税务接口 → `references/knowledge/investment/investment.md` 第九章
- WACC/DCF/终值建模机制、早期硬科技情景与期权估值 → `references/knowledge/investment/investment.md` 第三章、第八章
- ESG 因素识别 → `references/knowledge/compliance/esg.md`
- 评估基准日实时参数的官方来源 → `operations/source_directory.md`

## 执行步骤

### 步骤1：识别报告类型与审核维度
- 业务动作：读取报告，判定报告类型和价值类型，据此按 `references/knowledge/investment/asset_valuation_review.md` 第二章选定审核维度侧重。
- 输入：评估报告；输出：报告类型 + 拟审核维度清单。
- 所需能力：`document.extract`（PDF/图片报告）或宿主原生文件读取（Word/文本）。
- 降级：无提取能力且报告为扫描件 → 退回知识指引模式，请用户提供可读文本或逐段粘贴。

### 步骤2：提取基本信息与固化关键参数
- 业务动作：提取 10 项基本信息；从正文与评估说明固化 ≥8 项核心参数（WACC/Rf/β/MRP/ε/g/D/E/评估结论），每项记录取值与来源位置。
- 输出：基本信息表 + 关键参数清单（供步骤4交叉验证回读）。
- 门禁：10 项基本信息缺失标"未提取"；参数固化不全时不进入交叉验证。

### 步骤3：分维度审核
- 业务动作：按选定维度（D1 估值参数 / D2 关键假设 / D3 财务预测 / D4 法规合规 / D5 风险因素 / D6 ESG 行业）逐检查点比对报告，只对确定存在的问题生成 Finding，标 P0/P1/P2。
- 输入：报告正文 + 绑定知识；输出：分维度 Finding 清单。
- 所需能力：知识判断为主，无外部能力依赖。
- 降级：知识未覆盖的特殊评估对象 → 用相关知识 + 通用判断处理，并标注"该维度依据有限"。

### 步骤4：三方交叉验证（D7）
- 业务动作：对关键参数在报告正文、评估说明、Excel 底稿三个来源比对；对评估基准日实时公开参数（LPR/汇率/国债/股指）回官方来源核对当日值。
- 所需能力：`spreadsheet.read`（读 Excel 底稿）、`web.fetch`/`web.search`（核验实时参数，走 `operations/source_directory.md` 官方源）。
- 降级：无底稿 → D7 仅做报告内部一致性并说明；无联网能力 → 实时参数标"未验证"，不臆断一致。

### 步骤5：QSC 评分与审核结论
- 业务动作：按五维度加权评分并写扣分依据；按 P0/P1 数量判定"通过/有条件通过/不通过"。
- 输出：QSC 评分表 + 审核结论。
- 门禁：每个 Finding 满足三段式（问题描述+依据+建议），不达标标"描述不足"。

### 步骤6：生成审核报告
- 业务动作：汇总基本信息、交叉验证结果、分级 Finding、QSC 评分、审核结论、改进建议、审核说明（含 AI 能力边界披露）。
- 所需能力：`document.generate`。
- 降级：无文档生成能力 → 直接在对话中输出结构化审核结论与 Finding 清单。

## 工具选择与授权

- 依次发现并验证宿主原生能力、宿主 MCP、本机 CLI；按准确性、安全性、可验证性选择实现。
- 文本提取、Excel 读取、文档生成均为**读取与本地生成**，不涉及外部上传。若报告为敏感/涉密评估材料，联网核验实时参数前先提示用户数据范围，仅检索公开市场参数、不上传报告内容。
- 交叉验证联网仅用于核对公开市场参数（LPR/汇率/国债/股指），不得将报告或底稿数据传给第三方。

## 异常处理

- 报告为扫描件且无提取能力 → 退回知识指引模式，说明未实际读取。
- Excel 底稿缺失或格式损坏 → D7 降级为报告内部一致性，明确未做底稿比对。
- 实时参数无法联网核实 → 标"未验证实时参数"，不臆断一致。
- 准则/文号无法确认现行有效性 → Finding 中标"法规依据待核实"，不编造文号。
- 参数在报告不同位置矛盾 → 作为 D7 交叉验证 Finding 记录，不自行选一个当正确值。

## 复核检查点

- 统一复核总闸：四维自检（勾稽/依据现行/口径一致/引用核实）；审核结论属重大判断，叠加对立视角（评估机构 vs 委托人 / 报告使用方）。
- 专属业务验收：
  - 基本信息 10 项覆盖校验；关键参数固化 ≥8 项；
  - 每个 Finding 三段式达标、可追溯到报告原文位置；
  - QSC 每个维度扣分有对应 Finding 依据；
  - 审核结论与 P0/P1 数量判定规则一致；
  - 报告含 AI 能力边界披露。
- ⚠️ 文本提取成功、Excel 读取成功、报告生成成功都不等于审核完成——必须通过上述业务验收。

## 产出物

- 审核报告（Markdown 或用户指定格式），结构：审核信息与结论摘要 → 基本信息确认 → 三方交叉验证结果 → 审核发现（P0→P1→P2）→ QSC 评分及依据 → 审核结论 → 改进建议 → 审核说明（AI 能力边界）。
- 默认写入工具输出区（如 `gridman-tools/outputs/`）或用户指定位置；经用户复核确认为正式交付物后，才按 Mind 写入规则归档到 `gridman-mind/04_outputs/`。
- 命名建议：`资产评估审核报告_{报告文号或被评估单位}`。

## Mind 写入规则

- 仅在 Mind 已配置且事件值得留存时写入。
- 项目状态（某企业评估报告审核进度）→ `01_projects/{企业名}.md`。
- 经复核确认的正式审核报告 → `04_outputs/`。
- 审核中形成的重要判断理由 → `05_learning/judgments.md`；真实的审核误判或被用户纠正 → `05_learning/gotchas.md`。
- 未配置 Mind 或事件不值得留存 → 不写入，明确"本次不留存"。
