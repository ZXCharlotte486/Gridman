# 应收账款与收入审计

## 触发条件

用户要求：审计应收账款、营业收入、编制应收审定表、账龄分析、坏账准备复核、应收函证、收入截止测试、收入确认合规性、收入分析性程序时加载。

## 前置条件

必要材料：应收账款明细（按客户）、账龄数据、主营业务收入明细（按客户或产品）。

推荐材料：坏账计提政策与计提表、销售合同、发货与验收单据、开票与回款记录、期后回款数据、收入函证回函、关联方清单。

开始前确认：

1. 收入确认政策与时点（时段法/时点法）；
2. 是否适用新收入准则五步法；
3. 坏账准备计提方法（预期信用损失）；
4. 是否存在关联方销售与退货、返利。

收入确认与管理层凌驾按特别风险对待，排除需说明理由。

## 专业知识绑定

执行前读取：

- `references/knowledge/audit/audit_procedures.md`：收入循环、截止、账龄、函证；
- `references/knowledge/accounting/accounting_core.md`：收入确认五步法；
- 涉及舞弊迹象读取 `references/knowledge/analysis/financial_fraud.md`；
- 有序时账异常时衔接 `references/workflows/audit/journal_entry_testing.md` 的销售群异常凭证。

## 执行步骤

### 步骤1：应收与收入审定表

- 汇总应收账款、坏账准备、主营业务收入，与 TB、报表勾稽；
- 生成审定表（未审—调整—重分类—审定四栏）；
- 贷方余额应收重分类至预收/合同负债，单列标记。

**贷方余额必须逐户识别，不得只看科目合计。** 科目层面为借方余额时，明细层面仍可能存在贷方余额客户，合计会把两者轧掉。逐户算出期末余额后，对余额为负的客户全部列入重分类清单，并在账龄表中单列，不得把负数直接填进账龄分区当作"1年以内"等正常账龄。若客户方提供的账龄底稿已把负数填入分区，属于应予纠正的编制错误，须在结果中列明并提出重分类候选。

### 步骤2：账龄分析与坏账复核

执行重算前先完成三项前置，缺一项则重算结果不可用：

1. **按年度区块独立定位表头**：账龄底稿常把多个年度纵向排在同一工作表，且期初分区列随年份逐年增加（第一年只有"期初余额"，其后依次出现"期初1年内""期初1-2年""期初2-3年"……），后续账龄列整体右移。同一语义还存在多种写法（如"期初1年内"与"期初1年以内"），"期末余额"列在不同区块可能位于发生额之前、之后或缺失。必须对每个年度区块单独解析表头再定位字段，禁止用工作表首行的列位置套用到全表。
2. **先确定科目借贷方向**：应收类按「期末 = 期初 + 借方发生 − 贷方发生」，预收、应付等贷方性质科目按「期末 = 期初 + 贷方发生 − 借方发生」。方向判断错误时，差额恰为账龄合计的两倍，表现为大批量整齐不平，容易被误读成数据质量问题。方向须逐表确认并记录。
3. **建立账龄勾稽等式**：账龄各分区合计 = 该客户期末余额（容差需明确）。这是本步唯一可否证的验收式子，先建立再重算。

在此基础上：

- 按账龄区间分布应收余额；
- 复核账龄划分准确性（重新计算账龄），核对期初分区是否按年度正确滚动到下一区间；
- 按预期信用损失模型复核坏账计提充分性；
- 关注长账龄、重大单项、关联方应收；
- 输出《账龄分析表》与《坏账准备复核表》。

不平项必须逐条定位并分类为：科目方向判断错误、表头定位错误、底稿编制错误、数据缺失，四类处理方式不同，不得合并成"存在差异"一句话带过。

坏账计提不足或长账龄未减值的，列为调整或未更正错报候选。

### 步骤3：函证

- 按金额与风险选取函证样本（大额、异常、关联方、长账龄）；
- 编制应收函证清单，记录发收与回函一致性；
- 回函差异查明，未回函执行替代程序（合同+发货+回款）；
- 输出《应收函证控制表》。

函证由项目组独立控制，古立特做样本设计、汇总与差异比对，不代发、不假设回函。

### 步骤4：收入确认与截止测试

- 抽取报表日前后收入交易，核对发货/验收时点与确认时点；
- 判断是否存在提前或推迟确认；
- 检查退货、折让、返利的会计处理；
- 复核收入确认是否符合五步法；
- 输出《收入截止测试表》与《收入确认复核表》。

跨期确认必须定位到具体凭证与单据，不停在“可能跨期”。

### 步骤5：收入分析性程序

- 收入按月度、产品、客户结构分析；
- 毛利率趋势与同行对比；
- 收入与回款、与销项税勾稽；
- 单价与数量（量价）异常分析；
- 输出《收入分析性程序表》与异常清单。

### 步骤6：衔接分录测试结果

- 接收 `journal_entry_testing` 的销售群异常凭证；
- 对罕见科目组合（如收入对非往来科目）追加检查；
- 汇总应收与收入的例外事项和结论。

## 工具选择与授权

按顺序发现宿主表格/计算能力、已验证 MCP、本机 CLI。函证属外部程序，古立特不代发。默认写新文件，不改动原始明细。工具不可用时退回知识指引，给出账龄模板、函证清单、截止测试与五步法检查表。

## 异常处理

| 异常 | 处理 |
|---|---|
| 账龄起算口径不清 | 按凭证日期重算，标注口径 |
| 表头逐年漂移或同义列名不一致 | 按年度区块独立定位列，不沿用首行映射；记录各区块布局差异 |
| 有期末余额但账龄分区全空 | 单列「未划分账龄」，不按零处理，不代客户猜测分区 |
| 发生额为负（负数借方或负数贷方） | 单列并查明是冲销、红字还是录入错误，查明前不纳入账龄结论 |
| 账龄合计与期末余额不符 | 暂停坏账复核，先查明差异；不调节账龄分区去凑平余额 |
| 未回函 | 执行替代程序，记录未回函项 |
| 坏账政策与准则不符 | 单列差异，评估调整 |
| 期后回款数据缺失 | 标注替代证据不足，程序未完成 |
| 关联方收入占比高 | 加强真实性与披露检查 |
| 收入与销项税不符 | 定位差异，查确认或计税错误 |

## 复核检查点

统一复核总闸：交付前确认：

- [ ] 应收、坏账、收入审定表与 TB、报表勾稽；
- [ ] 每个年度区块的列布局已独立确认，未沿用首行映射；
- [ ] 科目借贷方向已确认，期末余额重算公式与方向一致；
- [ ] 逐行核对「账龄各分区合计 = 期末余额」，不平项已单列查明；
- [ ] 贷方余额应收已识别并重分类，未直接填入账龄分区；
- [ ] 账龄经重算，坏账计提充分性有结论；
- [ ] 函证样本覆盖大额/异常/关联方，差异已查；
- [ ] 未回函已执行替代程序，未假设一致；
- [ ] 收入截止测试定位到具体单据；
- [ ] 收入确认按五步法复核；
- [ ] 收入与回款、销项税勾稽；
- [ ] 分录测试销售群异常已回流处理；
- [ ] 未凭数据直接定性收入舞弊；
- [ ] 输出未覆盖源文件。

## 跨 Workflow 协作协议

- 有项目数据底座时，接收并更新 `references/workflows/audit/trial_balance_and_lead_schedules.md` 生成的应收与收入 Lead Schedule，不重复新建；独立运行且无底座时才创建审定表。
- 本流程只输出调整候选，不正式写入审定 TB。候选至少包含 `project_id`、`period`、`entity`、`source_version`、`workpaper_ref`、`candidate_id`、认定、借贷方向与金额、证据状态、建议依据、`source_workflow` 和 `conclusion_owner`；正式过账仅由 `references/workflows/audit/audit_adjustments_and_completion.md` 执行。
- 函证、截止和细节测试需要正式抽样时调用 `references/workflows/audit/audit_sampling.md`，接收并复用 `population_id`、`sample_id` 和选择记录。大额、关联方或异常项目可定向检查，但必须标记 `selection_type: targeted`，不得冒充代表性样本。
- 销售出库与 `references/workflows/audit/inventory_and_cost.md`、销项税与 `references/workflows/audit/taxes.md`、期后回款与 `references/workflows/audit/cash_and_bank.md` 共享 `sample_id`、`evidence_ref`、`cross_reference` 和 `conclusion_owner`。本流程拥有收入确认、应收余额、账龄和坏账结论；存货流程拥有出库与成本结论，税费流程拥有税额与申报结论，资金流程拥有银行流水证据结论。
