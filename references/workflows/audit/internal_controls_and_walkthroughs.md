# 内部控制了解、穿行与控制测试

## 触发条件

用户要求了解业务流程、编制流程图/控制矩阵、执行穿行测试、评价控制设计与实施、测试控制运行有效性、识别控制偏差或内控缺陷、决定是否依赖控制时加载。

仅询问 COSO、内控规范或关键控制点时读取 `references/knowledge/audit/internal_control.md` 直接回答。只做实质性程序且明确不拟依赖控制时，可以仅完成必要的控制了解，不强制执行运行有效性测试。

## 前置条件

必要材料：

- 主体、期间、流程范围和风险评估结果；
- 制度、流程说明、岗位职责、授权矩阵或系统配置；
- 关键控制执行记录、审批痕迹、异常处理记录或系统日志；
- 涉及财务报告的账户、认定和风险 ID。

开始前确认：

1. 目标是财务报表审计中的控制了解/控制测试，还是独立的内控评价/内控审计；
2. 涵盖哪些渠道、系统、地点和业务变体；
3. 是否拟依赖控制降低实质性程序范围；
4. 自动控制所依赖的 IT 一般控制是否在范围内；
5. 哪些现场访谈、观察或原件检查需由项目组完成。

资料不完整不阻塞建立初步流程，但不得据制度文本或单个签字直接认定控制有效。

## 专业知识绑定

执行前读取：

- `references/knowledge/audit/internal_control.md`：控制框架、双向穿行、设计/运行有效性和业务循环关键控制；
- `references/knowledge/audit/audit_procedures.md`：风险评估、控制测试与审计证据边界；
- `references/workflows/audit/materiality_and_risk_assessment.md`：风险 ID、认定与拟采取的审计应对；
- 需要抽样测试运行有效性时调用 `references/workflows/audit/audit_sampling.md`。

本 Workflow 是控制描述、`control_id`、穿行记录、控制测试与控制结论的唯一主责；风险评估 Workflow 拥有项目级重大错报风险，科目 Workflow 拥有账户和交易的最终专业结论。

## 执行步骤

### 步骤1：确定流程范围与财务报告关联

- 按业务循环、系统、地点、渠道和期间划定范围；
- 将流程连接到账户、报表项目、认定和风险 ID；
- 区分纯经营控制与可能防止、发现或纠正财务报表错报的控制；
- 输出《流程范围与风险映射表》。

经营控制不因“重要”自动进入财务报告控制测试；必须说明其失败如何影响具体账户或认定。

### 步骤2：记录流程和关键节点

- 记录业务发起、授权、执行、记录、保管、核对和异常处理；
- 覆盖直营网店、经销、平台、线下、手工补录、系统接口等重要变体；
- 识别职责分离、系统边界、人工干预和管理层凌驾路径；
- 为每个控制分配稳定 `control_id`；
- 输出《流程描述/流程图》和《风险控制矩阵（RCM）》初稿。

控制描述至少包含控制目标、执行人、频率、阈值/精度、证据、异常处理和所应对的风险。只写“经审批”或“系统自动控制”不构成完整描述。

### 步骤3：评价设计有效性

逐项判断：

- 控制按设计运行时能否防止或及时发现并纠正相关错报；
- 执行人是否具备权限、能力和独立性；
- 控制频率、阈值与精度是否足以应对风险；
- 异常是否有升级、调查和整改闭环；
- 自动控制依赖的访问、变更、运行和接口控制是否可靠。

制度存在、签字留痕或系统字段必填不能单独证明设计有效。设计无效的控制不进入依赖性运行测试，直接回传风险评估调整审计应对。

### 步骤4：执行双向穿行测试

- 选择代表性交易，从经营动作→单据→系统→财务记录追踪完整性与截止；
- 从财务记录→系统轨迹→单据→经营事实反向追踪发生/存在和权利义务；
- 询问执行人、观察关键动作、检查证据并在可行时重新执行；
- 记录流程偏差、未描述变体和控制实际执行方式；
- 输出《穿行测试记录表》并更新流程描述和 RCM。

穿行测试证明对流程的了解并评价控制是否已实施，通常不能单独证明整个期间持续有效。未实际访谈、观察或检查原件时，只能列计划和待办，不能填写已实施结论。

### 步骤5：确定关键控制与依赖策略

- 基于风险、认定和控制精度识别关键控制；
- 区分预防性/检查性、人工/自动、交易层/管理层复核控制；
- 记录拟依赖程度、测试期间、频率和证据来源；
- ITGC 不可靠时，重新评价依赖自动控制和系统生成信息的可行性；
- 输出《关键控制与测试策略表》。

是否依赖控制由审计策略决定。不能为了减少实质性程序而先假定控制有效。

### 步骤6：设计并执行运行有效性测试

- 为每个 `control_id` 定义测试属性、预期证据、偏差标准和执行责任；
- 需要选样时向 `references/workflows/audit/audit_sampling.md` 提交控制总体、频率、可容忍/预计偏差率和测试目标，接收正式 `sample_id`；
- 对样本检查执行人、日期、证据、复核精度和异常处理；
- 自动控制测试配置和变更；管理层复核控制测试其数据完整性、阈值和跟进；
- 输出《控制测试表》。

签字本身不是测试结论。必须检查控制执行了什么、是否及时、是否有足够信息以及异常是否得到处理。

### 步骤7：评价偏差与控制缺陷

- 汇总偏差数量、类型、原因、期间分布和是否系统性；
- 区分偶发执行偏差、设计缺陷、未实施控制和管理层凌驾；
- 考虑补偿性控制及其证据；
- 结合错报可能性、潜在金额和定性因素评价一般/重要/重大缺陷建议；
- 输出《控制偏差与缺陷评价表》。

缺陷等级是专业判断。单一示例阈值不能机械替代项目标准；内控审计意见和缺陷最终定级由有权项目负责人作出。

### 步骤8：回传风险应对并形成结论

- 将控制结论和缺陷回传 `references/workflows/audit/materiality_and_risk_assessment.md`，更新控制风险和风险—认定—程序矩阵；
- 向科目 Workflow 提供可依赖的 `control_id`、测试期间、偏差和限制；
- 控制不可靠时扩大或改变实质性程序，不把“已测试”写成“有效”；
- 汇总需治理层/管理层沟通及待整改事项；
- 输出《内控了解与控制测试结论表》。

## 跨 Workflow 协作协议

- 本 Workflow 唯一维护 `control_id`、流程/控制描述、穿行记录、控制测试和控制结论，其他 Workflow 只引用，不重复建立同一控制。
- `references/workflows/audit/materiality_and_risk_assessment.md` 唯一维护风险 ID 和项目级风险评级；本流程回传控制风险影响，不覆盖其风险台账。
- `references/workflows/audit/audit_sampling.md` 唯一维护正式控制测试总体、`sample_id` 和偏差率计算；本流程拥有测试属性、证据评价和控制结论。
- 科目 Workflow 引用控制结果决定实质性程序，但仍独立拥有交易、余额和列报结论。
- 共同字段至少包括 `project_id`、`period`、`entity`、`source_version`、`workpaper_ref`、`risk_id`、`control_id`；抽样时另含 `population_id`、`sample_id`、`evidence_ref` 和 `conclusion_owner`。

## 工具选择与授权

依次发现宿主文档/表格能力、已验证 MCP、本机 CLI。默认写新底稿，不修改客户制度、系统配置或审批记录。系统操作、外部写入、上传、覆盖、删除和批量修改前必须确认。

能力不足时退回知识指引模式，提供流程描述、RCM、穿行记录、控制测试和缺陷评价模板，并明确未实际访谈、观察、取样或检查证据。

## 异常处理

| 异常 | 处理 |
|---|---|
| 流程描述与实际不一致 | 以已验证事实更新流程并保留版本差异 |
| 只有制度没有执行证据 | 仅评价设计，运行有效性标为未测试 |
| 穿行交易不代表重要变体 | 补充变体穿行，不以单一路径覆盖全部渠道 |
| 自动控制但 ITGC 不可靠 | 不依赖或增加替代程序，回传风险评估 |
| 控制样本出现偏差 | 查明原因，评价系统性并按抽样规则考虑扩大 |
| 管理层凌驾 | 直接提高风险，衔接分录测试和实质性程序 |

## 复核检查点

- [ ] 流程范围覆盖重要渠道、系统、地点和业务变体；
- [ ] 风险、账户、认定与 `control_id` 双向映射；
- [ ] 控制描述包含执行人、频率、精度、证据和异常处理；
- [ ] 设计有效性、实施状态和运行有效性分开评价；
- [ ] 穿行测试双向实施或如实标记未完成；
- [ ] 正式控制样本使用统一 `sample_id` 并可追溯；
- [ ] 签字或制度文本未被当成充分证据；
- [ ] 控制偏差和缺陷已回传风险及实质性程序；
- [ ] 未自动出具内控审计意见或替代项目负责人定级。

## 产出物

建议命名：`主体_期间_内控了解与控制测试_版本_日期`。

最低产出：流程范围与风险映射、流程描述/流程图、RCM、穿行测试记录、关键控制策略、控制测试表、缺陷评价和结论表。

## Mind 写入规则

只记录跨会话项目状态、控制测试进度、缺陷状态和输出索引；不把员工姓名、权限明细、系统配置、日志或未脱敏控制证据写入跨项目记忆。
