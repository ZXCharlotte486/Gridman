# 审计抽样设计与样本治理

## 触发条件

用户要求设计审计样本、确定样本量、随机/系统/货币单元抽样、控制测试抽样、细节测试抽样、扩大样本、评价样本偏差或投射错报时加载。

仅询问抽样概念且没有总体数据、不要求形成样本时，读取审计知识直接回答。风险定向检查、全量测试和统计抽样必须明确区分；不得把高风险项目定向选取冒充随机样本，也不得给非统计抽样附加虚假的置信水平。

## 前置条件

必要材料：

- `project_id`、主体、期间和来源版本；
- 明确的审计目标、相关认定、风险 ID 与执行该程序的主责 Workflow；
- 抽样总体、抽样单元、总体规模/金额及可核对的控制总数；
- 重要性、实际执行重要性、可容忍错报或可容忍偏差率、预计错报或预计偏差率；
- 拟采用的测试类型：控制测试或实质性细节测试。

开始前确认：

1. 总体是否与审计目标一致并覆盖完整期间；
2. 抽样单元是一笔交易、一个余额、一个控制执行实例还是其他对象；
3. 是否有必须 100% 检查的重大、异常或特别风险项目；
4. 是否允许统计投射，还是只做非统计/定向选择；
5. 由哪个专项 Workflow 执行样本程序并拥有专业结论。

总体无法核对完整性、参数缺失或抽样单元不明确时，不得生成看似精确的样本量；先输出资料缺口和设计待确认项。

## 专业知识绑定

执行前读取：

- `references/knowledge/audit/audit_procedures.md`：审计抽样、风险应对与审计证据边界；
- `references/workflows/audit/materiality_and_risk_assessment.md`：重要性与风险参数；
- 控制测试抽样同时读取 `references/knowledge/audit/internal_control.md`，并衔接 `references/workflows/audit/internal_controls_and_walkthroughs.md`；
- 具体业务判断由对应科目或专项 Workflow 提供。

本 Workflow 只负责总体治理、抽样设计、样本编号、选择复现和偏差/错报评价，不执行函证、监盘、原件核对等现场程序，也不替代专项 Workflow 对样本证据作专业结论。

## 执行步骤

### 步骤1：定义审计目标与总体

- 记录程序目标、相关认定、风险 ID、主责 Workflow 和结论所有人；
- 定义总体边界、抽样单元、期间、来源文件与 `source_version`；
- 建立 `population_id`，记录总体笔数、金额及控制总数；
- 区分完整总体、排除项目和单独 100% 检查项目。

总体边界变化必须生成新版本，不得在已抽样后静默增删记录。

### 步骤2：验证总体完整性与可抽性

- 将总体笔数和金额与总账、明细账、控制日志或其他可靠来源勾稽；
- 检查重复、缺号、空值、负数、冲销、多币种和异常期间；
- 记录排除规则、排除数量/金额及理由；
- 输出《抽样总体完整性检查表》。

总体不完整时暂停正式选择。可以先生成修复清单，但不得把不完整总体产生的样本表述为代表总体。

### 步骤3：选择抽样方法与参数

- 控制测试根据控制频率、可容忍偏差率、预计偏差率和拟依赖程度设计；
- 细节测试根据账面金额、可容忍错报、预计错报、风险和总体特征设计；
- 根据目标选择随机、系统、货币单元、分层或非统计方法；
- 重大、异常和特别风险项目可单独 100% 检查，不混入代表性样本；
- 记录方法、参数、判断理由和限制。

非统计抽样必须明确判断依据；定向选取标记为 `selection_type: targeted`，不得对未随机总体作统计投射。

### 步骤4：生成可复现样本

- 冻结总体版本并保存排序规则；
- 随机方法记录随机种子或等价的可复现参数；
- 系统抽样记录起点、间隔及总体排序；
- 货币单元抽样保留累计金额、抽样间隔和命中逻辑；
- 为每个项目分配唯一 `sample_id`，不得因跨 Workflow 使用而重新编号；
- 输出《样本选择表》和《抽样设计备忘录》。

工具无法保证可复现时，退回人工可复核的系统选择或知识指引，不声称已完成随机抽样。

### 步骤5：分发样本并承接测试结果

每条样本至少传递：

- `project_id`、`period`、`entity`、`population_id`、`source_version`；
- `sample_id`、`selection_type`、`lead_workflow`、`workpaper_ref`；
- `evidence_ref`、`cross_reference`、`conclusion_owner`；
- 账面金额、测试金额、偏差/错报金额、测试状态与例外类型。

专项 Workflow 实施合同、凭证、函证、盘点或重算等程序并回填结果。本 Workflow 不改写专项结论，只检查结果字段是否完整、样本是否遗漏及例外是否已归类。

### 步骤6：评价偏差、错报与扩大样本

- 控制测试汇总偏差数量、偏差率、原因和是否系统性；
- 细节测试汇总事实错报、判断错报和推断错报；
- 仅对设计允许的代表性样本进行投射，并保留投射方法；
- 单独 100% 检查项目和定向选取项目不向剩余总体机械投射；
- 比较可容忍偏差/错报，考虑定性严重性和特别风险；
- 需要扩大样本时记录触发原因、增量范围和新版本。

不得因样本“未发现异常”直接推出总体无错报。例外原因未查明时，不得只靠增加样本掩盖问题。

### 步骤7：形成抽样结论并回传

- 输出总体完整性结论、抽样方法、样本覆盖、例外汇总、投射结果和局限；
- 将控制测试抽样结果回传 `references/workflows/audit/internal_controls_and_walkthroughs.md`；
- 将细节测试结果回传对应科目 Workflow；
- 需要调整的事项由科目 Workflow形成 `candidate_id`，本 Workflow 不直接提出会计调整；
- 输出《抽样评价表》与《样本状态跟踪表》。

## 跨 Workflow 协作协议

- 本 Workflow 是 `population_id`、正式抽样口径、`sample_id`、选择复现信息和投射结果的唯一主责。
- 风险评估 Workflow 提供风险与重要性参数；内控或科目 Workflow 提供程序目标、认定、总体来源并拥有专业结论。
- 同一交易跨采购、存货、应付、收入、税费等循环时只保留一个 `sample_id` 和主测试底稿；其他流程引用相同 `evidence_ref`，只补充本循环判断。
- 专项 Workflow 可以识别高风险定向项目，但不得自行把定向项目扩展为统计总体或重编号正式样本。
- 独立运行且没有项目级抽样治理时，可以生成一次性样本，但仍须保留完整字段和复现参数，后续并入项目时不得覆盖既有编号。

## 工具选择与授权

依次发现宿主表格/计算能力、已验证 MCP、本机 CLI。默认生成新底稿，不覆盖总体源文件。随机选择和统计计算必须保存参数与中间量。上传第三方、写入外部系统、覆盖或删除数据前必须确认。

能力不足时退回知识指引模式，提供总体检查表、参数表、样本选择模板和评价公式，并明确未实际完成选择或计算。

## 异常处理

| 异常 | 处理 |
|---|---|
| 总体与账表不勾稽 | 暂停正式抽样，查明差异或限定总体并披露 |
| 样本量参数缺失 | 输出待确认参数，不机械套固定数量 |
| 随机结果不可复现 | 重新使用可记录种子/起点的方法并版本化 |
| 样本证据缺失 | 标记未完成并退回主责 Workflow 补证 |
| 例外集中于某类项目 | 分层分析并考虑扩大或改为定向检查 |
| 跨 Workflow 重复抽样 | 合并到原 `sample_id`，保留交叉引用和新增判断 |

## 复核检查点

- [ ] 审计目标、认定、风险 ID 与总体边界一致；
- [ ] 总体笔数和金额已与可靠来源勾稽；
- [ ] 100% 检查、统计样本、非统计样本和定向项目已区分；
- [ ] 方法、参数、随机种子/起点和总体版本可复现；
- [ ] 每个样本有唯一 `sample_id`、证据索引和结论所有人；
- [ ] 例外与错报评价考虑金额和性质；
- [ ] 只对适当总体作投射，未夸大非统计样本结论；
- [ ] 扩大样本有原因和版本记录；
- [ ] 未把抽样结果冒充最终科目或审计意见。

## 产出物

建议命名：`主体_期间_审计抽样_版本_日期`。

最低产出：抽样总体完整性检查表、抽样设计备忘录、样本选择表、样本状态跟踪表、例外/错报评价表及抽样结论。

## Mind 写入规则

只记录跨会话项目状态、样本版本和输出索引；不把完整交易总体、客户/供应商信息、凭证内容或未脱敏证据写入跨项目记忆。
