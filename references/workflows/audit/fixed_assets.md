# 固定资产审计

## 触发条件

用户要求固定资产审计、卡片账勾稽、折旧重算、资产增减测试、固定资产盘点、在建工程转固或固定资产减值检查时加载。

## 前置条件

必要材料：固定资产卡片或明细台账、总账/TB、折旧计提表。

推荐材料：采购合同、发票、验收单、付款记录、权属证明、处置审批、盘点表、在建工程明细、预算决算和减值评估资料。

开始前确认：资产类别、折旧政策、预计使用年限、残值率、折旧方法、启停日期、组件化核算、权属和抵押情况。

缺少实物盘点、原始单据或权属证明时，可完成账面分析与重算，但存在性、权利义务和新增真实性程序必须标为未完成。

## 专业知识绑定

执行前读取：

- `references/knowledge/audit/audit_procedures.md`：固定资产循环和实质性程序；
- `references/knowledge/accounting/accounting_core.md`：固定资产确认、初始计量、折旧与处置；
- 涉及减值时读取相应会计知识章节。

接收数据底座的固定资产审定表、风险评估参数和分录测试中的资产类异常凭证。

## 执行步骤

### 步骤1：审定表与台账勾稽

- 按类别汇总原值、累计折旧、减值准备和净值；
- 勾稽卡片账、明细账、总账、TB 与报表；
- 验证期初 + 增加 − 减少 = 期末；
- 输出《固定资产审定表》和《增减变动勾稽表》。

### 步骤2：新增资产测试

- 按重大金额、异常供应商、期末集中新增和分录测试结果选样；
- 检查合同、发票、验收、付款和达到预定可使用状态日期；
- 区分资本性支出与修理费用；
- 检查借款费用、安装调试及可归属成本；
- 输出《固定资产新增测试表》。

缺原件时仅列待核，不得确认新增真实或资本化正确。

### 步骤3：减少与处置测试

- 检查报废、出售、盘亏、转出审批及处置价款；
- 重算累计折旧转销和处置损益；
- 检查长期闲置或已不存在资产是否仍挂账；
- 输出《固定资产减少与处置测试表》。

### 步骤4：折旧重算

- 按类别核对折旧方法、年限、残值率和起止日期；
- 重算本期折旧并与账面比较；
- 检查新增、减少、停用、改扩建和已提足折旧资产；
- 将折旧费用勾稽至生产成本、制造费用、管理费用等；
- 输出《折旧重算表》。

会计估计变更必须区分为未来适用，不得追溯改写历史折旧，除非属于前期差错。

### 步骤5：实物盘点与权属检查

- 生成从账到实物、从实物到账的双向抽盘清单；
- 记录资产编号、地点、使用部门、状态及差异；
- 检查房屋、车辆、设备等权属证明和抵押限制；
- 输出《固定资产盘点表》和《权属及受限资产检查表》。

未实际观察或核对原件时，只能生成计划和待办，不能填写实施结论。

### 步骤6：在建工程转固与减值迹象

- 检查达到预定可使用状态但未转固、已转固但仍归集支出等情形；
- 勾稽工程合同、进度、验收和转固时点；
- 识别闲置、损坏、技术淘汰、经营恶化等减值迹象；
- 有迹象时取得可收回金额测算依据；
- 输出《在建工程转固检查表》和《减值迹象检查表》。

### 步骤7：截止、列报与结论

- 检查期末前后新增、处置和转固的入账期间；
- 检查原值、累计折旧、减值、在建工程和受限资产披露；
- 汇总差异、待补证和调整建议；
- 将调整传递给完成阶段 Workflow。

## 工具选择与授权

依次发现宿主表格/文档能力、已验证 MCP、本机 CLI。默认生成新底稿，不修改卡片账或总账。外部上传、批量改账、覆盖和删除前必须确认。

## 异常处理

| 异常 | 处理 |
|---|---|
| 卡片账与总账不符 | 按类别、资产编号追踪差异，不强行调平 |
| 缺启用日期或折旧参数 | 列参数缺口，无法可靠重算的样本单列 |
| 资产编号重复 | 结合地点、序列号和取得日期确认，不擅自合并 |
| 在建工程长期挂账 | 检查工程状态与转固条件，列高风险事项 |
| 权证名称不一致 | 获取法律关系和权属证据，不能仅凭账面判断 |
| 无减值测算依据 | 披露估计不确定性并要求补证 |

## 复核检查点

- [ ] 卡片账、总账、TB 与报表已勾稽；
- [ ] 增减变动公式成立，差异有解释；
- [ ] 新增和处置样本可追溯支持证据；
- [ ] 折旧参数、公式和结果可复核；
- [ ] 实物盘点和权属程序实施状态如实记录；
- [ ] 在建工程转固时点和减值迹象已检查；
- [ ] 列报披露和受限资产已覆盖；
- [ ] 调整建议未覆盖源数据。

## 产出物

建议命名：`主体_期间_固定资产审计_版本_日期`。

最低产出：固定资产审定表、增减测试、折旧重算、盘点计划/结果、权属与受限检查、转固与减值检查、结论及调整建议。

## 跨 Workflow 协作协议

- 有项目数据底座时，接收并更新 `references/workflows/audit/trial_balance_and_lead_schedules.md` 生成的固定资产 Lead Schedule，不重复新建；独立运行且无底座时才创建。
- 本流程只输出调整候选，不正式写入审定 TB。候选至少包含 `project_id`、`period`、`entity`、`source_version`、`workpaper_ref`、`candidate_id`、认定、借贷方向与金额、证据状态、建议依据、`source_workflow` 和 `conclusion_owner`；正式过账仅由 `references/workflows/audit/audit_adjustments_and_completion.md` 执行。
- 新增、处置或盘点需要正式抽样时调用 `references/workflows/audit/audit_sampling.md`；本流程只能提出重大或异常定向项，不自行改变正式总体、样本编号或投射口径。
- 与 `references/workflows/audit/payables_and_purchases.md` 共用的资产新增样本共享 `lead_workflow`、`sample_id`、`evidence_ref`、`cross_reference` 和 `conclusion_owner`；本流程拥有资本化、启用时点与折旧结论，采购流程拥有交易发生证据结论。

## Mind 写入规则

只记录跨会话项目状态、输出索引和经确认的可泛化判断；不记录完整资产卡片、地址、证照号码或未脱敏合同。
