# 货币资金审计

## 触发条件

用户要求：审计货币资金、库存现金、银行存款、其他货币资金，编制银行余额调节表、货币资金审定表、函证控制表，检查受限资金、大额异常收付时加载。

## 前置条件

必要材料：货币资金各科目期末余额、银行存款明细（按账户）、银行对账单或企业日记账。

推荐材料：银行询证函回函、定期存款单、承兑汇票与保证金台账、大额收付款凭证、外币折算依据、开户清单。

开始前确认：

1. 涉及账户清单是否完整（本外币、基本户、一般户、专户）；
2. 是否存在受限资金（保证金、冻结、质押）；
3. 是否已发出银行函证及回函情况；
4. 报表日与截止时点。

缺银行对账单或回函不阻塞账面分析，但调节表和函证结论必须标注“未取得外部证据，程序未完成”。

## 专业知识绑定

执行前读取：

- `references/knowledge/audit/audit_procedures.md`：货币资金循环、银行余额调节、函证规则；
- 涉及外币折算读取 `references/knowledge/accounting/` 对应内容。

## 执行步骤

### 步骤1：货币资金构成与审定表

- 汇总库存现金、银行存款、其他货币资金各明细；
- 与 TB、报表货币资金项目勾稽；
- 生成货币资金审定表（未审—调整—重分类—审定四栏）；
- 标记外币账户及折算汇率。

### 步骤2：银行余额调节表

- 以银行对账单余额与企业账面余额为两端；
- 列示未达账项（企业已记银行未记、银行已记企业未记）；
- 调节后双方余额应一致；
- 输出各账户《银行余额调节表》。

调节不平或无对账单时，单列差异并标注未完成，不强行调平。

### 步骤3：函证控制

- 编制银行询证函清单（每个账户、含已销户账户）；
- 记录发函日期、收函日期、回函一致性；
- 回函差异逐项查明；
- 输出《银行函证控制表》。

函证必须由项目组独立控制发收，古立特只做清单、汇总与差异比对，不得代替函证程序或假设回函结果。

### 步骤4：库存现金与收付测试

- 现金余额合理性（与业务规模比）；
- 大额、整数、频繁现金收付抽查；
- 现金盘点由项目组现场执行，本步骤生成盘点表模板与账面数；
- 抽查大额银行收付款的授权与用途。

### 步骤5：受限资金与截止

- 识别保证金、冻结、质押等受限资金，评估列报与披露；
- 报表日前后大额收付的截止测试；
- 输出《受限资金清单》与《货币资金截止测试表》。

受限资金必须评估是否应重分类或披露，不得混入非受限货币资金。

## 工具选择与授权

按顺序发现宿主表格/计算能力、已验证 MCP、本机 CLI。函证发收属项目组控制的外部程序，古立特不代发。默认写新文件，不覆盖原始对账单与凭证。工具不可用时退回知识指引，给出调节表、函证清单与截止测试模板。

## 异常处理

| 异常 | 处理 |
|---|---|
| 无银行对账单 | 只做账面分析，调节表标注未完成 |
| 回函未收到 | 记录未回函账户，评估替代程序，不假设一致 |
| 调节表不平 | 列差异查未达账项或错账，未平不下结论 |
| 外币折算差异 | 核对汇率与折算，差异计入汇兑损益复核 |
| 存在未入账账户 | 追加账户，评估完整性风险 |

## 复核检查点

统一复核总闸：交付前确认：

- [ ] 账户清单完整，含本外币与专户；
- [ ] 货币资金审定表与 TB、报表勾稽；
- [ ] 每个账户有银行余额调节表或已标注缺证；
- [ ] 函证清单覆盖全部账户，回函差异已查；
- [ ] 受限资金已识别并评估列报披露；
- [ ] 截止测试覆盖报表日前后大额收付；
- [ ] 现场盘点与函证未被表述为已由古立特完成；
- [ ] 输出未覆盖源文件。

## 跨 Workflow 协作协议

- 有项目数据底座时，接收并更新 `references/workflows/audit/trial_balance_and_lead_schedules.md` 生成的货币资金 Lead Schedule，不重复新建；独立运行且无底座时才创建审定表。
- 本流程只输出调整候选，不正式写入审定 TB。候选至少包含 `project_id`、`period`、`entity`、`source_version`、`workpaper_ref`、`candidate_id`、认定、借贷方向与金额、证据状态、建议依据、`source_workflow` 和 `conclusion_owner`；正式过账仅由 `references/workflows/audit/audit_adjustments_and_completion.md` 执行。
- 银行账户清单、函证控制和余额调节由本流程主责。账户是否全量函证按项目判断；对收付款明细实施正式抽样时调用 `references/workflows/audit/audit_sampling.md`，复用其 `population_id`、`sample_id` 和选择记录。
- 收款样本与 `references/workflows/audit/receivables_and_revenue.md`、付款样本与 `references/workflows/audit/payables_and_purchases.md` 共享 `sample_id`、`evidence_ref`、`cross_reference` 和 `conclusion_owner`。本流程拥有银行流水、资金受限及调节结论，交易循环拥有业务发生、截止和会计处理结论。
