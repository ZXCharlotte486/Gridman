# 会计分录测试与序时账异常筛选

## 触发条件

用户要求执行或设计以下任务时加载：会计分录测试、JET、序时账清洗、异常凭证筛选、凭证巡检、科目组合异常、跨业务群异常、对方科目分析、多借多贷拆分、管理层凌驾相关分录筛选。

仅询问概念或公式、没有提供数据且不要求产出时，读取 `references/knowledge/audit/journal_entry_analytics.md` 直接回答，不假装执行本 Workflow。

## 前置条件

必要材料：

- 序时账文件，优先 XLSX/CSV；
- 唯一凭证标识；
- 一级科目；
- 借方金额、贷方金额。

推荐材料：凭证日期、摘要、二级/明细科目、制单人、审核人、录入时间、账套/公司、附件数。

开始前必须向用户确认或明确记录：

1. 分析期间、主体和账套；
2. 凭证号是否在该范围内唯一；
3. 金额精度和借贷平衡容差；
4. 是否存在多币种、红字、冲销、合并凭证或迁移数据；
5. 输出位置与是否允许生成文件；
6. 风险排序用途是审计抽样、内控巡检还是财务清洗。

缺少摘要、制单人或录入时间不阻塞基础结构分析，但必须在结果中标明相应测试未执行。缺少唯一凭证号、一级科目或借贷金额时，不得执行凭证级模型；先提供字段补齐或映射清单。

## 专业知识绑定

执行前读取：

- `references/knowledge/audit/journal_entry_analytics.md`：分录特征、业务群、PMI、跨群/群内评分、对方科目算法；
- `references/knowledge/audit/audit_procedures.md`：风险评估、重要性与审计证据边界。

如任务涉及舞弊动机或收入造假，再读取：

- `references/knowledge/analysis/financial_fraud.md`。

本 Workflow 的统计筛选基准不得冒充审计重要性。高风险凭证不得直接表述为错报或舞弊。

## 执行步骤

### 步骤1：建立输入快照与字段映射

- 记录源文件名、工作表、文件大小、修改时间和可用时的哈希值；
- 映射凭证号、日期、一级科目、明细科目、摘要、借贷金额及人员字段；
- 保留原始列，新增标准化列，不覆盖源数据；
- 输出《字段映射与数据限制表》。

所需能力：表格读取、字段识别。

降级：无法自动识别时，列出候选列和样例值，请用户确认映射；不得猜测金额列或凭证号列。

### 步骤2：执行数据完整性检查

检查并量化：

1. **凭证键候选对比（必做，先于其他检查）**：至少并列测试「年度+凭证字+凭证号」「年月+凭证字+凭证号」「完整日期+凭证字+凭证号」三种键，对每种输出凭证数、每张平均行数、最大行数和结构类型分布，再选定键并记录理由。
2. 原始行数、凭证数、期间范围；
3. 必填字段空值和非数值金额；
4. 每张凭证借贷差额；
5. 重复凭证号、跨期间同号；
6. 借贷同时有值、同时为零、异常负数；
7. 科目名称前后空格、别名和编码冲突；
8. 数据是否覆盖全部月份及全部账套。

**凭证序号按期间循环是常见记账习惯**（同一「记N/序号N」在每个月各出现一次）。此时年度级键会把多张凭证误合并为一张，而借贷总额聚合前后不变、每张"凭证"仍然平衡，因此借贷平衡检查和总额勾稽都发现不了。必须靠本步第 1 项主动识别，不能等到发现不平才处理。

出现下列任一信号时，先回到第 1 项复核键定义，不得直接进入后续步骤：

- 每张凭证平均行数明显偏高（经验参考：超过 8 行）；
- 多借多贷占比明显偏高（经验参考：超过 40%）；
- 同一「凭证字+凭证号」跨多个期间重复出现；
- 凭证数与主体业务规模、期间长度明显不匹配。

输出《数据质量检查表》，须载明选定的键定义、被排除的候选键及排除理由。存在系统性不平、凭证号无法唯一聚合或明显缺月时，暂停风险打分，先让用户决定修复或限定分析范围。

### 步骤3：构建凭证级基础表

按唯一凭证聚合，生成：

- 科目集合与会计分录特征；
- 借方科目集合、贷方科目集合；
- 借贷绝对金额合计；
- 行数、科目数；
- 摘要集合、制单人集合；
- 结构类型：1借1贷、1借多贷、多借1贷、多借多贷、全借全贷候选、特殊结转候选。

验收：聚合前后借贷总额一致；每个结果可回钻到原始行。

「凭证数等于唯一凭证键数量」是聚合动作的自洽检查，任何键定义都会通过，**不能用它证明键选对了**。键的正确性由步骤2第 1 项的候选对比负责；本步只需复述选定键，并确认结构类型分布未落入步骤2列出的复核信号。

### 步骤4：识别硬规则与排除项

先识别：

- 期间损益结转；
- 资金内部往来；
- 汇兑损益候选；
- 红字冲销、反向分录；
- 自动结转或批量导入凭证。

硬规则命中凭证仍保留在底稿中，但从不适用的统计训练或异常模型中排除。每条排除必须记录规则、命中字段和凭证号，禁止静默过滤。

### 步骤5：构建业务群与分录特征统计

- 按科目强锚、二元锚和停用词规则归入采购、销售、薪酬、生产、研发、长期资产、资金、税务、其他群；
- 同时保留主群和全部涉及群；
- 汇总每种分录特征的凭证数、金额、借贷模式和示例；
- 业务群词表先采用通用表，再用本企业科目表校准。

降级：无法可靠归群时保留“其他/待判断”，不得为了覆盖率强行分类。

### 步骤6：计算结构关系与异常分量

按数据量和宿主能力选择：

**基础模式（必须可执行）**

- 分录特征频次；
- 科目连接频次；
- 单群/跨群标记；
- 群内罕见连接频次；
- 分群金额排序与筛选基准。

**增强模式（能力满足时）**

- PMI 科目共现矩阵；
- Noisy-OR 群共现率与群距离；
- HHI 自适应群内异常分；
- 连续金额衰减 alpha；
- 结构、关键词、金额和人员分量化分类。

输出必须分别列示 `Score_cross`、`Score_inner`、`alpha` 和总分。若未执行增强模型，应明确写“基础频次模式”，不得伪造公式得分。

### 步骤7：解析多借多贷对方科目

仅对确有需要的凭证执行：

1. 简单结构直接配对；
2. 全借全贷候选先转换为分析视图，但保留原始符号；
3. 多借多贷使用金额上限、动态剩余值、至多一次轧差进行剪枝；
4. 优先从科目数量较多的一侧匹配数量较少的一侧；
5. 小额或可选资源少的行优先；
6. 用连接数和拆分惩罚排序候选方案；
7. 导出全部合理候选和默认方案供人工选择。

若组合数量爆炸、凭证不平或存在多币种未折算，停止穷举并标记“无法可靠解析”，不得只输出第一个找到的方案。

### 步骤8：形成风险排序与抽查建议

风险清单至少分为：

- 高风险待复核：跨远群、大额且罕见、结构无法解释；
- 中风险待复核：单项异常明显或多个弱信号叠加；
- 低风险/长尾：罕见但金额较小；
- 已解释：有充分业务解释和证据；
- 确认异常：经人工检查证据后确认。

抽查建议同时覆盖：高分项目、重大金额项目、罕见结构、管理层/特殊人员分录、期末分录和少量随机样本，避免只检查模型高分而遗漏模型盲区。

### 步骤9：人工复核与反馈闭环

对每张被复核凭证记录：复核人、日期、证据、业务解释、结论、原分类、纠正分类、原对方科目方案、新方案及理由。

只有在用户明确要求并允许持久化时，才将纠错写入项目记忆或模型配置。纠错数据按账套/主体隔离，不向第三方传输，不跨客户复用具体科目模式。

### 步骤10：生成底稿和管理摘要

建议产出：

1. `会计分录测试_数据质量.xlsx`；
2. `会计分录测试_风险清单.xlsx`；
3. `会计分录测试_对方科目候选.xlsx`（适用时）；
4. `会计分录测试_方法与结论.md`；
5. 可选的群距离热力图和科目连接图。

方法说明必须列明：分析范围、字段、排除规则、模型版本、参数、未执行测试、数据限制、风险等级口径和证据边界。

## 工具选择与授权

按以下顺序发现能力：

1. 宿主原生表格/代码执行能力；
2. 已配置并可验证的 MCP 数据处理能力；
3. 本机 Python/PowerShell 等 CLI。

不得把某个具体工具写成唯一实现。工具不可用时，退回知识指引模式，提供字段映射、公式、伪代码和检查表，并明确没有实际处理数据。

读取用户明确提供的本地文件属于任务必要操作。以下动作执行前必须单独确认：上传第三方服务、写入外部系统、覆盖源文件、批量改账、删除数据。所有分析默认写入新文件，不修改原始序时账。

## 异常处理

| 异常 | 处理 |
|---|---|
| 文件加密或损坏 | 报告具体错误，请用户提供可读副本；不尝试绕过密码 |
| Excel 超大导致内存不足 | 分块读取，但按完整凭证边界聚合；验证分块前后总额 |
| 凭证号不唯一 | 组合账套+公司+年度+期间+凭证字+凭证号建立键，并请用户确认 |
| 借贷不平 | 单列异常；在原因未明确前不进入对方科目穷举 |
| 科目名称混乱 | 建映射表，保留原值和标准值；映射不确定项交人工确认 |
| 模型无解 | 输出无解原因和受影响凭证，不强制生成对方科目 |
| 候选方案过多 | 设置组合上限，按复杂度排序并标记未完全穷举 |
| 重复执行 | 比较数据哈希和输出路径，避免重复学习或覆盖旧结果 |
| 参数改变 | 记录新旧参数并生成新版本输出，不覆盖原结果 |

## 复核检查点

统一复核总闸：工具执行成功不等于业务完成。交付前逐项确认：

- [ ] 分析主体、期间、账套和唯一凭证键已明确；
- [ ] 原始行数、凭证数、借贷总额可与源数据勾稽；
- [ ] 所有静默过滤已消除，排除规则可追溯；
- [ ] 业务群和科目词表已按企业科目表校准或标记限制；
- [ ] 风险总分可拆回跨群、群内和金额分量；
- [ ] 数据分析筛选基准未被称为审计重要性；
- [ ] 多借多贷候选满足金额上限、动态余额和双向自洽；
- [ ] 高风险未直接写成错报、舞弊或审计结论；
- [ ] 抽查范围包含模型盲区和随机样本；
- [ ] 输出未覆盖源文件，敏感数据未传往未知第三方；
- [ ] 所有未执行程序和数据限制已披露。

## 产出物

底稿命名建议：`主体_期间_会计分录测试_版本_日期`。

最低验收标准：

- 数据质量表能勾稽源数据；
- 风险清单每行可回钻原始凭证；
- 每个风险等级有明确口径；
- 公式、参数和排除规则写入方法说明；
- 对方科目方案同时保留候选、默认选择和人工结论；
- 输出不包含未经证据支持的确定性舞弊结论。

## 跨 Workflow 协作协议

- 本 Workflow 唯一维护分录数据质量、异常评分、筛选理由和 `je_candidate_id`；筛选结果只是审计线索，不是正式样本、错报或舞弊结论。
- 高风险、期末、特殊人员和罕见结构项目可作为 `selection_type: targeted` 候选；需要代表性或随机抽样时，将总体来源、风险分层和候选条件交给 `references/workflows/audit/audit_sampling.md`，由其维护 `population_id`、`sample_id`、选择复现信息和投射结果。
- 本 Workflow 不自行给定向项目编制正式 `sample_id`，不把风险筛选基准称为审计重要性，也不对定向项目作统计投射。
- 异常凭证按业务群回传对应科目 Workflow，由其检查证据、形成专业结论并在需要时提出 `candidate_id`；本流程不直接提出会计调整或正式过账。
- 跨流程传递至少包含 `project_id`、`period`、`entity`、`source_version`、`workpaper_ref`、`je_candidate_id`、风险分数与分量、筛选理由、业务群和证据状态。

## Mind 写入规则

仅在 Mind 已配置且确有跨会话价值时写入：

- `01_projects/current.md`：分析主体、期间、输入、当前步骤、输出路径；
- `01_projects/user_prefs.md`：用户确认的长期输出偏好，不记录客户敏感数据；
- `04_outputs/`：最终交付物索引；
- `05_learning/judgments.md`：经人工确认、可泛化的专业判断；
- `05_learning/error_log.md`：真实工具或数据处理错误；
- `05_learning/gotchas.md`：真实发生且可复用的判断错误。

不得把客户完整序时账、人员姓名、银行账号或未脱敏凭证内容写入跨项目记忆。没有真实错误或长期价值时不为满足流程而写入。
