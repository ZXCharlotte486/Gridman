# 重要性水平测算与风险评估

## 触发条件

用户要求：计算重要性、实际执行重要性、明显微小错报临界值、做风险评估、识别重大错报风险、特别风险、建立风险—认定—程序矩阵、初步分析程序时加载。

## 前置条件

必要材料：本期财务数据（至少利润表和资产负债表主要项目）、分析期间、主体。

推荐材料：上期审定数、行业数据、报表附注、管理层背景、以前年度底稿。

开始前确认：

1. 主体性质（营利/上市/非营利）与所处行业；
2. 报表使用者及其关注点；
3. 是否首次审计；
4. 是否已知舞弊线索或监管关注。

## 专业知识绑定

执行前读取：

- `references/knowledge/audit/audit_procedures.md`：风险评估、重要性、内控框架；
- `references/knowledge/audit/audit.md`：审计理论与风险模型；
- 涉及舞弊时读取 `references/knowledge/analysis/financial_fraud.md`；
- 涉及内控时读取 `references/knowledge/audit/internal_control.md`。

## 执行步骤

### 步骤1：选择重要性基准

- 根据主体性质选基准：营利企业常用税前利润，收入或资产规模波动大时用营业收入或总资产；
- 说明选择理由；
- 记录基准金额来源（未审/调整后）。

盈利临界或异常波动时，需说明是否改用更稳定基准。

### 步骤2：测算重要性

- 整体重要性 = 基准 × 比例（按判断区间，说明取值理由）；
- 实际执行重要性 = 整体 × 比例（通常 50%–75%，风险高取低）；
- 明显微小错报临界值 = 整体 × 较小比例；
- 输出《重要性测算表》，含判断说明，可复制入底稿。

比例取值必须给理由，不套固定数字了事。

### 步骤3：初步分析程序

- 本期与上期科目金额、结构比、变动率；
- 关键比率：流动比率、周转率、负债率、毛利率、现金流匹配等；
- 标记异常：大幅波动、从无到有、比率恶化、利润与现金流背离；
- 输出《初步分析程序表》与风险信号清单。

异常必须转化为具体风险描述，不停在"波动较大"。

### 步骤4：识别重大错报风险

- 按重要账户和认定评估固有风险（性质、复杂度、估计、波动）；
- 为每项风险分配稳定且项目内唯一的 `risk_id`，记录账户、认定、风险描述、来源版本、风险所有人和状态；
- 结合内控了解评估控制风险；
- 重大错报风险 = 固有 × 控制；
- 识别特别风险（收入确认、管理层凌驾、重大估计、关联方、非常规交易）；
- 输出《重大错报风险清单》。

收入确认与管理层凌驾按准则默认作为特别风险考虑，排除需说明理由。风险变化时保留原 `risk_id` 和版本历史；风险实质改变时新建编号并交叉引用，不静默覆盖。

### 步骤5：建立风险—认定—程序矩阵

对每个重要账户/认定：

- 记录 `risk_id`、风险等级及其与账户、认定的映射；
- 记录拟采用程序的性质、时间、范围和结论所有人；
- 记录是否需控制测试及拟引用的 `control_id`；
- 记录是否纳入分录测试定向筛查或正式抽样设计；
- 输出《风险应对矩阵》，供内控、分录测试、科目 Workflow 与抽样调用。

### 步骤6：接收回流并衔接后续程序

- 将重要性和稳定 `risk_id` 传给抽样、内控、科目程序及调整完成阶段；
- 特别风险账户标记加强程序；
- 管理层凌驾风险与 `references/workflows/audit/journal_entry_testing.md` 挂钩，但异常分录线索不直接改变风险结论；
- 接收 `references/workflows/audit/internal_controls_and_walkthroughs.md` 返回的 `control_id`、设计/实施/运行结论、偏差和限制，重新评价控制风险；
- 控制不可靠、证据不足或控制结论变化时，版本化更新风险—认定—程序矩阵，并明确扩大或改变的实质性程序；
- 输出可传递的风险参数汇总和回流变更记录。

## 跨 Workflow 协作协议

- 本 Workflow 唯一维护项目级 `risk_id`、重要性参数、风险评级和风险—认定—程序矩阵；其他 Workflow 引用并回传证据，不另建平行风险台账。
- `references/workflows/audit/internal_controls_and_walkthroughs.md` 唯一维护 `control_id` 与控制结论；本流程据其回流更新控制风险，不覆盖控制测试底稿。
- `references/workflows/audit/audit_sampling.md` 使用本流程提供的重要性、风险和认定参数维护正式总体与样本；本流程不生成 `sample_id`。
- `references/workflows/audit/journal_entry_testing.md` 提供异常分录候选和风险分层输入；本流程评价其对项目风险的影响，不把模型高分直接认定为错报或舞弊。
- 科目 Workflow 引用 `risk_id` 实施程序并回传例外、证据限制和调整候选；项目级风险结论仍由本流程版本化维护。
- 共同字段至少包含 `project_id`、`period`、`entity`、`source_version`、`workpaper_ref`、`risk_id` 和 `conclusion_owner`。

## 工具选择与授权

按顺序发现宿主表格/计算能力、已验证 MCP、本机 CLI。行业或外部数据需联网时先确认，不向未知第三方传数据。工具不可用时退回知识指引，给出基准选择表、比例区间、比率公式与矩阵模板。

## 异常处理

| 异常 | 处理 |
|---|---|
| 亏损或利润临界 | 改用更稳定基准并说明 |
| 缺上期数据 | 用行业或多期趋势替代，标注局限 |
| 数据不完整 | 就可用部分分析，明确未覆盖范围 |
| 首次审计 | 期初余额风险单独评估 |
| 行业异常 | 结合行业特征判断，不机械套区间 |

## 复核检查点

统一复核总闸：交付前确认：

- [ ] 基准选择有理由，金额来源清晰；
- [ ] 三档重要性齐全，比例取值有依据；
- [ ] 初步分析异常已转为具体风险；
- [ ] 重大错报风险按账户/认定评估；
- [ ] 特别风险已识别，排除项有说明；
- [ ] 风险应对矩阵可传递给后续程序；
- [ ] 重要性未与统计筛选基准混称；
- [ ] 未凭数据直接定性舞弊。
