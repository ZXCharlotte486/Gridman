# 试算平衡表初始化与科目审定表

## 触发条件

用户要求：导入试算平衡表、建 TB、科目映射报表、编制审定表（Lead Schedule）、未审数上期审定数对接、TB 与报表勾稽、底稿数据底座时加载。

## 前置条件

必要材料：本期未审 TB（科目、期初、本期发生、期末余额）、本期财务报表。

推荐材料：上期审定 TB、科目对照表、总账明细账、报表项目映射规则、事务所审定表模板。

开始前确认：

1. TB 层级（一级科目还是含明细）；
2. TB 是否已结账、是否含损益结转；
3. 报表项目与科目的映射口径；
4. 合并还是单体；
5. 是否提供上期审定数。

缺上期审定数不阻塞，但期初栏标注"期初未审定"。

## 专业知识绑定

执行前读取：

- `references/knowledge/audit/audit_procedures.md`：报表填列、重分类、审定表逻辑；
- 需要科目性质判断时读取 `references/knowledge/accounting/` 相关文件。

## 执行步骤

### 步骤1：TB 导入与结构校验

- 读取未审 TB，识别科目编码、名称、期初、借贷发生额、期末；
- 校验：期初 + 本期借 − 本期贷 = 期末（按科目方向）；
- 校验全表借贷平衡；
- 保留原始列，新增标准化列。

输出《TB 校验表》。不平衡且未查清前，不生成审定数。

### 步骤2：科目映射到报表项目

- 将 TB 科目映射到资产负债表、利润表项目；
- 处理备抵科目、跨项目科目、往来重分类；
- 标记需重分类科目（如一年内到期的非流动资产、预付预收对冲）；
- 输出《科目—报表项目映射表》。

映射不确定项交人工确认，不擅自归并。

### 步骤3：TB 与报表勾稽

- 按映射汇总 TB 得出报表项目金额；
- 与用户提供报表逐项比对；
- 列出差异并定位原因（映射、重分类、结转、过账）；
- 输出《TB—报表勾稽表》。

### 步骤4：接入上期审定数

- 导入上期审定 TB 或报告数；
- 本期期初与上期期末勾稽；
- 差异标记（前期调整、会计政策变更、重述）；
- 无上期审定数时标注"期初未审定"并评估影响。

### 步骤5：生成科目审定表（Lead Schedule）骨架

按报表项目或重要科目生成审定表，每张含：

- 上期审定数、本期未审数；
- 审计调整栏、重分类栏；
- 本期审定数（公式联动）；
- 变动额与变动率；
- 索引号、数据来源、编制/复核占位。

审定数 = 未审数 + 审计调整 + 重分类，三栏必须公式贯通。

### 步骤6：底座完整性检查

- 所有科目已映射，无遗漏无重复；
- 审定表合计与 TB、报表可勾稽；
- 每张审定表可回钻 TB 与明细；
- 输出《数据底座完整性检查表》。

## 工具选择与授权

按顺序发现：宿主原生表格能力 → 已验证 MCP → 本机 CLI。工具不可用时退回知识指引模式，提供映射模板、审定表模板与勾稽公式。默认写新文件，不覆盖源 TB 与报表。

## 异常处理

| 异常 | 处理 |
|---|---|
| TB 不平衡 | 单列差额，查过账或导出错误，未平不生成审定数 |
| 科目含混合明细 | 拆分或标注，映射不确定交人工 |
| 报表与 TB 差异 | 列差异并定位，不强行调平 |
| 期初与上期期末不符 | 查前期调整/重述，标注差异 |
| 多期或多账套 | 按主体和期间分开，不混算 |

## 复核检查点

统一复核总闸：交付前确认：

- [ ] TB 借贷平衡、逐科目余额关系成立；
- [ ] 全部科目已映射报表项目；
- [ ] TB 汇总与报表可勾稽，差异有说明；
- [ ] 期初与上期审定数勾稽或已标注未审定；
- [ ] 审定表未审数、调整、重分类、审定数四栏贯通；
- [ ] 每张审定表可回钻来源；
- [ ] 输出未覆盖源文件。

## 产出物

命名建议：`主体_期间_TB与审定表_版本_日期`。

最低验收：TB 校验表、映射表、勾稽表、审定表骨架齐全，且相互勾稽、可回钻。

## 跨 Workflow 协作协议

- 本 Workflow 是 TB 标准化、科目—报表映射、勾稽关系和 Lead Schedule 骨架的唯一主责；通过 `source_version` 标识每一版底座，其他 Workflow 不另建平行底座。
- Lead Schedule 中“审定数 = 未审数 + 调整 + 重分类”仅定义字段和公式关系。本 Workflow 不批准调整、不把候选写入正式调整栏，也不发布最终审定 TB。
- 科目 Workflow 接收并更新既有 Lead Schedule 的程序结果、证据索引和调整候选交叉引用；独立运行且没有项目底座时才创建临时审定表，后续并入时保留来源版本。
- `references/workflows/audit/audit_adjustments_and_completion.md` 唯一负责接受候选、正式过账、生成最终审定 TB 和维护未更正错报；其发布的新版本回传本流程用于最终勾稽，不反向覆盖未审底座。
- 跨流程传递至少包含 `project_id`、`period`、`entity`、`source_version`、`workpaper_ref`、科目/报表项目映射和底座状态。

## Mind 写入规则

仅在 Mind 已配置且有跨会话价值时写入：

- `01_projects/current.md`：TB 版本、映射口径、勾稽状态；
- `05_learning/error_log.md`：真实数据错误；
- `05_learning/gotchas.md`：真实可复用的映射/勾稽判断坑。

不写入客户完整账套与敏感明细。
