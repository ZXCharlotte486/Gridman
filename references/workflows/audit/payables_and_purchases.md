# 应付账款与采购审计

## 触发条件

用户要求应付账款审计、采购循环测试、供应商账龄、应付函证、采购截止、未入账负债、暂估应付或期后付款检查时加载。

## 前置条件

必要材料：应付账款明细、采购明细或总账、TB、供应商主数据。

推荐材料：采购合同、订单、入库单、发票、付款记录、供应商对账单、期后银行流水、暂估清单、关联方清单。

开始前确认：主体与期间、供应商唯一标识、借贷余额口径、暂估与发票匹配规则、采购入账和付款流程、多币种及关联方情况。

缺少函证回函、合同、发票、入库单或银行原件时，可完成账面分析，但完整性、存在性和截止结论必须保留待办。

## 专业知识绑定

执行前读取：

- `references/knowledge/audit/audit_procedures.md`：采购循环、函证、截止和未入账负债；
- 按需读取会计与税务知识文件；
- 异常供应商或采购分录读取 `references/knowledge/audit/journal_entry_analytics.md`。

接收 TB 审定表、风险评估参数以及 `references/workflows/audit/journal_entry_testing.md` 的采购群异常凭证。

## 执行步骤

### 步骤1：审定表与明细勾稽

- 汇总应付账款、应付票据、预付账款及暂估相关余额；
- 勾稽供应商明细、总账、TB 和报表；
- 识别借方余额、负余额、长期无变动和关联方余额；
- 输出《应付账款审定表》和《供应商余额勾稽表》。

### 步骤2：账龄与异常余额分析

- 按可复核口径计算账龄；
- 分析长期挂账、借方余额、期末突增、零采购大额应付和频繁冲销；
- 与采购额、付款额和上期余额交叉比较；
- 输出《应付账款账龄及异常分析表》。

账龄起点不明确时必须说明采用发票、入库或挂账日期，不能混用。

### 步骤3：供应商函证

- 按重大金额、异常余额、零余额但交易频繁、关联方和随机样本选样；
- 编制函证控制表，记录地址核验、发出、回函和差异；
- 未回函设计替代程序：合同、发票、入库、期后付款和对账单；
- 输出《应付账款函证控制表》和《函证差异处理表》。

古立特可生成函证清单和控制表，但未由项目组控制发函与回函时不得写“函证已实施”。

### 步骤4：采购发生与三单匹配测试

- 从采购明细和异常凭证选样；
- 核对订单/合同、入库验收、发票和付款；
- 检查数量、单价、税额、供应商及审批；
- 识别重复发票、拆单、异常供应商和无入库采购；
- 输出《采购发生测试表》。

### 步骤5：采购截止测试

- 选取资产负债表日前后入库、发票、记账和付款记录；
- 按控制权或验收口径判断负债和存货确认期间；
- 检查在途物资、暂估入库、退货和跨期发票；
- 输出《采购截止测试表》。

不得仅按发票日期判断截止，必须结合入库、验收和合同条款。

### 步骤6：未入账负债检查

- 检查期后付款、期后发票和期后入库对应的期前义务；
- 检查未结采购订单、供应商对账差异、暂估及费用计提；
- 对大额期后付款追溯至期末是否应确认负债；
- 输出《未入账负债检查表》。

该步骤以完整性为核心，不能只从期末应付余额正向抽样。

### 步骤7：暂估、预付与重分类

- 检查暂估依据、期后发票匹配和冲回；
- 识别同一供应商借贷余额是否满足抵销条件；
- 应付借方余额和预付贷方余额按实质提出重分类建议；
- 输出《暂估与重分类检查表》。

不得机械按负号重分类，需结合合同、结算和法律抵销权。

### 步骤8：列报、结论与调整

- 检查关联方、账龄、担保、票据及流动性分类披露；
- 汇总函证差异、截止、未入账负债和重分类事项；
- 将调整建议传递给 `references/workflows/audit/audit_adjustments_and_completion.md`；
- 输出《应付与采购审计结论表》。

## 工具选择与授权

依次发现宿主表格/文档能力、已验证 MCP、本机 CLI。默认生成新底稿，不修改供应商主数据或账务。对外发函、上传第三方、外部写入、覆盖和删除前必须确认。

## 异常处理

| 异常 | 处理 |
|---|---|
| 供应商名称不统一 | 建立编码/名称映射，保留原值 |
| 借贷余额混杂 | 分交易和法律关系判断，不直接净额抵销 |
| 无账龄起点 | 选择可验证日期并披露口径限制 |
| 函证地址由被审计单位单独提供 | 通过独立来源核验，无法核验则提高风险 |
| 期后付款数据不完整 | 将未入账负债程序标为受限 |
| 暂估长期未冲 | 追踪业务实质和发票状态，列异常事项 |

## 复核检查点

- [ ] 明细、总账、TB 与报表已勾稽；
- [ ] 账龄口径统一且异常余额已跟进；
- [ ] 函证控制责任和实施状态如实记录；
- [ ] 采购测试覆盖合同、入库、发票、付款与审批；
- [ ] 截止判断不只依赖发票日期；
- [ ] 未入账负债包含期后付款和反向完整性检查；
- [ ] 暂估、预付和重分类按业务实质处理；
- [ ] 调整建议可追溯且未覆盖源数据。

## 产出物

建议命名：`主体_期间_应付与采购审计_版本_日期`。

最低产出：应付审定表、账龄分析、函证控制表、采购发生测试、截止测试、未入账负债检查、暂估与重分类、结论及调整建议。

## 跨 Workflow 协作协议

- 有项目数据底座时，接收并更新 `references/workflows/audit/trial_balance_and_lead_schedules.md` 生成的应付与采购 Lead Schedule，不重复新建；独立运行且无底座时才创建。
- 本流程只输出调整候选，不正式写入审定 TB。候选至少包含 `project_id`、`period`、`entity`、`source_version`、`workpaper_ref`、`candidate_id`、认定、借贷方向与金额、证据状态、建议依据、`source_workflow` 和 `conclusion_owner`；正式过账仅由 `references/workflows/audit/audit_adjustments_and_completion.md` 执行。
- 函证、采购发生、截止或期后付款需要正式抽样时调用 `references/workflows/audit/audit_sampling.md`；本流程只能提出重大、异常或高风险定向项，不自行改变正式总体、样本编号或投射口径。
- 本流程是采购发生、采购截止和未入账负债的默认主责；与 `references/workflows/audit/inventory_and_cost.md`、`references/workflows/audit/fixed_assets.md`、`references/workflows/audit/taxes.md` 共享样本时记录 `lead_workflow`、`sample_id`、`evidence_ref`、`cross_reference`、`conclusion_owner`，其他流程引用证据并补充各自结论。

## Mind 写入规则

只记录跨会话项目状态、输出索引和经确认的可泛化判断；不得记录完整供应商清单、银行账号、联系人或未脱敏合同发票。
