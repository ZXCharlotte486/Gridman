# 审计调整与完成阶段

## 触发条件

用户要求：汇总审计调整、编制调整分录、重分类、未更正错报汇总、评价错报影响、结出审定数、报表与附注勾稽、形成审计结论、完成阶段复核时加载。

## 前置条件

必要材料：未审 TB、各科目审计结论及建议调整、重要性水平。

推荐材料：报表及附注、上期审定数、往来与关联方信息、待决事项清单。

开始前确认：

1. 分析主体、期间与适用准则；
2. 重要性和实际执行重要性；
3. 调整是否已与管理层沟通；
4. 报表版本与列报格式。

本 Workflow 汇总调整并评价影响，最终审计意见由注册会计师作出，不得自动生成审计结论定性。

## 专业知识绑定

执行前读取：

- `references/knowledge/audit/audit_procedures.md`：完成阶段、重分类、错报评价；
- `references/knowledge/audit/audit.md`：审计意见类型与完成阶段要求；
- 涉及准则列报读取 `references/knowledge/accounting/` 对应文件。

## 上游数据契约与过账边界

本 Workflow 是正式调整过账、最终审定 TB 和未更正错报汇总的唯一主责。下文“过入”仅指写入受控的审计底稿与审定 TB 新版本，不代表修改客户总账、ERP 或报表系统；任何外部写入均不属于本 Workflow 默认范围，必须另行取得授权。

每条上游调整候选至少包含：`project_id`、`period`、`entity`、`source_version`、`workpaper_ref`、`candidate_id`、事项、科目、认定、借贷方向与金额、证据状态、建议依据、`source_workflow` 和 `conclusion_owner`。字段不全、证据未就绪或来源版本失效的候选退回补充，不直接过账。

候选按以下状态流转：`proposed` → `evidence_ready` → `audit_approved` → `management_accepted` / `management_rejected`。`proposed`、`evidence_ready` 和尚未取得管理层决定的 `audit_approved` 均属于未决；审计否决、候选撤回或被新候选替换时分别标记 `audit_rejected`、`withdrawn` 或 `superseded`。只有经授权复核且被管理层接受的调整进入审定 TB；管理层拒绝的事项进入未更正错报汇总。所有状态变化和重新提交均保留历史，不覆盖原记录。

以 `candidate_id` 为主键，并结合主体、期间、科目、金额和来源底稿检查重复或相互影响。每次正式过账记录源版本、目标版本、过账人/复核人占位和时间；同一候选不得在多个 Workflow 并行过账。

## 执行步骤

### 步骤1：归集调整与重分类事项

- 汇总各科目 Workflow 提出的调整和重分类；
- 每条记录：来源底稿、事项、科目、金额、借贷方向、依据、认定；
- 区分更正错报调整与重分类（重分类不影响利润）；
- 输出《调整与重分类汇总表》。

每条调整必须可追溯到支持性底稿，无依据的不入表。

### 步骤2：编制调整分录并过入

- 为每条事项编制规范分录；
- 检查分录借贷平衡；
- 将调整过入各科目和 TB；
- 结出审定数；
- 验证审定 TB 借贷平衡。

### 步骤3：汇总未更正错报

- 管理层未接受的调整列入未更正错报汇总（含事实错报、判断错报、推断错报）；
- 记录对资产、负债、损益、权益的影响；
- 考虑前期未更正错报的本期影响。

### 步骤4：评价错报影响

- 已更正、未更正错报分别与重要性比较；
- 单条及汇总评价；
- 评价错报性质（是否涉及舞弊迹象、趋势操纵、临界调节）；
- 输出《错报影响评价表》与是否需进一步调整的结论建议。

金额低于重要性但性质严重的错报，必须单独说明，不因金额小而放过。

### 步骤5：报表与附注勾稽

- 审定 TB 与报表勾稽；
- 报表项目间勾稽（如未分配利润滚动、现金流与资产负债变动）；
- 报表与附注数据一致性；
- 输出《报表勾稽检查表》与差异清单。

### 步骤6：完成阶段复核清单

- 汇总未决事项、缺失资料、待管理层确认项；
- 特别风险应对是否充分；
- 期后事项、持续经营、关联方、或有事项是否已考虑；
- 底稿索引与交叉引用完整性；
- 输出《完成阶段复核清单》与《审计总结备忘录》初稿。

审计意见类型仅作依据整理和初步建议，最终由项目负责人判断。

## 工具选择与授权

按顺序发现宿主表格/计算能力、已验证 MCP、本机 CLI。所有调整写入新版本底稿，不覆盖未审原始数据。工具不可用时退回知识指引，给出调整汇总模板、错报评价表和勾稽清单。

## 异常处理

| 异常 | 处理 |
|---|---|
| 调整后仍不平 | 定位差错来源，未平前不结审定数 |
| 调整相互影响 | 按逻辑顺序过账，重算受影响科目 |
| 缺依据的调整 | 退回对应科目补证，不强行入表 |
| 附注与报表不符 | 单列差异，交人工确认口径 |
| 重要性变化 | 重估错报影响并留版本记录 |

## 复核检查点

统一复核总闸：交付前确认：

- [ ] 每条调整可追溯到支持底稿；
- [ ] 调整分录借贷平衡，审定 TB 平衡；
- [ ] 更正与未更正错报区分清晰；
- [ ] 错报已按金额与性质双重评价；
- [ ] 报表与附注勾稽一致，差异有说明；
- [ ] 完成阶段复核清单覆盖期后、持续经营、关联方等；
- [ ] 未自动定性舞弊或直接生成最终审计意见；
- [ ] 输出未覆盖原始数据。

## 产出物

命名建议：`主体_期间_调整与完成_版本_日期`。

最低验收：调整汇总表、审定 TB、未更正错报汇总、错报影响评价、报表勾稽表、完成阶段复核清单齐全且相互勾稽。

## Mind 写入规则

仅在 Mind 已配置且有跨会话价值时写入：

- `01_projects/current.md`：调整数、审定数、未决事项、结论状态；
- `04_outputs/`：最终底稿索引；
- `05_learning/judgments.md`：经确认可泛化的调整与列报判断；
- `05_learning/error_log.md`：真实计算或勾稽错误。

不写入客户敏感明细与未脱敏数据。
