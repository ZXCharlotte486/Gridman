# 国有企业经济责任审计

## 触发条件

用户提出对国企领导人员的离任/任中经济责任审计、编制经济责任审计方案、界定经济责任、按被审计单位类型选择专项审计模块，或提及“经济责任审计/离任审计/两办新规45号/直接责任领导责任”等。

一般财务报表审计走事务所审计工作流；企业内审通用事项按 `references/knowledge/audit/internal_audit.md` 处理；政府/行政事业单位收支审计按 `references/knowledge/audit/internal_audit.md` 第八章处理。

## 前置条件

- 明确被审计领导人员、任职期间起止、被审计单位类型（集团总部/二级子企业/境外业务/上市控股/混改）。
- 取得任期经营业绩责任书、上级任务书；缺失则先向委托方索取，不凭印象设定考核目标。
- 无制度依据的事项不进入实质查证；判断标准以国家级/上级级/本单位三级制度为准。

## 专业知识绑定

- 流程、评价、责任界定、模块适用矩阵 → `references/knowledge/audit/soe_economic_responsibility_audit.md`
- 审计发现公文化重述与语言规范 → `references/knowledge/audit/internal_audit.md`（审计发现报告撰写）
- 内控/治理/舞弊等专项判断 → `references/knowledge/audit/internal_control.md`、`references/knowledge/analysis/financial_fraud.md`
- 涉及资产评估复核的模块 → `references/workflows/investment/asset_valuation_report_review.md`

## 执行步骤

### 步骤1：查制度依据（不可跳过）
- 业务动作：按国家级/上级级/本单位三级体系，为拟审事项找判断标准。
- 输出：制度依据清单；无依据事项不进入查证。

### 步骤2：取考核目标
- 业务动作：取任期经营业绩责任书、上级任务书，梳理任期考核指标。
- 输出：考核指标清单。

### 步骤3：定审计内容与重点
- 业务动作：按五维度（应做未做/制度齐备/怎么做的/效果如何/财务合规）确定内容；按被审计单位类型用适用矩阵选必审 + 选审专项模块。
- 输出：审计内容清单 + 拟审模块清单。

### 步骤4：了解情况与风险评估
- 业务动作：了解责任部门/业务流程/内控/决策/计划，初评风险定策略。
- 输出：风险等级 + 审计策略。

### 步骤5：完善审计计划
- 业务动作：据范围、风险、重点编制审计方案。
- 输出：审计方案。

### 步骤6：审计查证
- 业务动作：非财务7项通用程序（分析资料/取验收评价报告/走访座谈/实地察看/访谈受益人/其他职能部门核实/咨询专家）+ 财务收支审计 + 选定专项模块查证。
- 所需能力：知识判断为主；取证材料为扫描件时用 `document.extract`，涉及台账/明细表时用 `spreadsheet.read`。
- 降级：无提取/表格能力 → 退回知识指引模式，请用户提供可读材料或数据，明确未实际处理。

### 步骤7：评价与责任界定
- 业务动作：按评价7维度写实评价；对每条问题按职责分工界定直接责任/领导责任，落实“三个区分开来”。
- 门禁：只对审计查证范围内事项评价；未涉及事项不作评价；每条评价有证据支撑。

### 步骤8：撰写报告与跟踪整改
- 业务动作：按四要素（总体评价/主要业绩/问题与责任认定/审计建议）成文；建立整改台账。
- 所需能力：`document.generate`。

## 工具选择与授权

- 依次发现并验证宿主原生能力、宿主 MCP、本机 CLI；`current.md` 历史能力记录仅作提示，执行前实时验证。
- 取证材料多含敏感人事、经营与廉政信息，上传外部服务前必须说明范围并取得用户确认，先询问是否脱敏；不向未知第三方传输。
- 生成报告写入本地产出目录前，若覆盖已有文件需确认。

## 异常处理

- 制度依据缺失 → 该事项不定性，标“依据待核实”，不编造文号。
- 材料/数据缺失 → 记录缺什么、为什么需要、替代来源，不臆断结论。
- 责任事实不充分 → 不强行界定直接/领导责任，标“证据不足待补充”。
- 无外部能力 → 退回知识指引模式，提供程序、清单与模板，明确哪些未实际执行。

## 复核检查点

- 统一复核总闸：依据现行、口径一致、引用可核；重大责任认定加多视角与对抗者视角。
- 专属验收：制度依据齐备；模块选择与单位类型匹配；评价不超查证范围；责任界定基于职责分工且证据充分；“三个区分开来”已落实；每条问题满足“事实+依据+建议”。
- 工具调用成功不等于业务完成，须通过上述验收。

## 产出物

- 经济责任审计方案、专项模块工作底稿、经济责任审计报告（四要素）、整改台账。
- 报告默认写入工具产出目录，经复核确认为正式交付物后按 Mind 写入规则归档。

## Mind 写入规则

- 项目状态与进度 → `01_projects/{项目名}.md`
- 经复核确认的正式审计报告 → `04_outputs/`
- 重大责任界定判断理由 → `05_learning/judgments.md`
- 查证或路由中的真实错误 → `05_learning/error_log.md` / `route_failures.md`
- 未配置 Mind 或未命中持久化事件 → 不写入，并说明“本次不留存”。
