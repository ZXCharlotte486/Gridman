# 路由执行流程

> 本文件是路由的“执行流程”（程序）——定义阶段②→③→④ 怎么流转、怎么判断、怎么降级。
>
> 路由的“映射表”（数据）在 `operations/routing_index.md`。
>
> 何时读本文件：阶段②（判断是否需要外部数据或副作用）、阶段③（执行）、阶段④（交付前复核）时读取。


## 一、路由总览

```
用户问题
    │
    ▼
① 定位专业领域与任务形态
    ├─ 轻量场景 → 直接答
    └─ 专业任务 → 先走 operations/routing_index.md 的领域路由
         ├─ 可直接回答或仅需指导式 Workflow → 不强制调用外部能力
         └─ 需要外部数据或产生副作用 → 进入执行流程
    │
    ▼
② 执行（仅在任务确有能力需求时）
    ├─ 宿主原生能力可用 → 验证后使用
    ├─ 宿主 MCP 可用 → 验证连接、权限与参数后使用
    ├─ 本机 CLI 可用 → 验证后使用
    └─ 全无 → 退回“知识指引模式”
    │
    ▼
③ 复核 + 交付
```


## 二、任务形态判断（阶段②入口）

```
用户问题
    │
    ▼
是轻量场景吗？（“你是谁”）
    ├─ 是 → 直接答（SKILL.md 自我介绍模板），跳过后续所有流程
    └─ 否 → 继续
    │
    ▼
按 operations/routing_index.md 的 L-1/L0/L1 定位专业领域
    └─ 在命中的 knowledge 子树内受限发现候选，并按任务需要判断是否加载匹配 Workflow
    │
    ▼
任务是否需要获取外部数据，或产生上传、写入、覆盖、删除、批量修改等副作用？
    ├─ 否 → 使用 knowledge 直接回答，或以 Workflow 组织指导步骤；不为“执行感”强行调用工具
    └─ 是 → 进入阶段③执行流程
```

领域路由只决定搜索边界，不直接假定具体文件。禁止扫描整个 `references/`；允许在已命中的领域子树内按文件名、文件头和适用场景渐进发现。Workflow 可以编排纯指导任务，也可以声明外部能力需求，不固定属于“知识类”或“能力类”任一侧。


## 三、执行流程（阶段③执行）

### 能力发现顺序

```
宿主原生能力 → 宿主已配置的 MCP 工具 → 本机可用 CLI → 知识指引模式
```

这不是对具体工具的永久绑定。每次执行都要重新确认能力当前可用，并按准确性、安全性、可验证性和成本选择实现。宿主 MCP 属于宿主执行环境，不属于古立特本体。

### 检测与执行流程

```
收到"帮我做/算/生成/查"类请求
    │
    ▼
① 若存在且命中具体 Workflow，由其声明本步输入、输出和抽象能力需求；否则依据 knowledge 与本文件的通用流程声明
    │
    ▼
② 发现候选能力
    ├─ 宿主原生能力（Web Fetch / 文件读写 / 终端命令等）
    ├─ 宿主已配置且当前连接的 MCP 工具
    └─ 本机 Tools 根目录中由 `provider.json` 声明的 CLI
    │
    ▼
③ 验证并选择
    ├─ 本机 CLI 校验 `provider.json` 声明的能力 ID、入口脚本和平台是否匹配
    ├─ 执行无敏感数据的离线检查，验证连接、权限和参数
    ├─ 涉及上传、外部写入、覆盖、删除或批量修改 → 先取得用户确认
    ├─ provider 声明代码级授权闸 → 必须传递对应授权，不得用提示文字代替或绕过
    └─ 选择最安全、可验证且满足任务要求的实现
    │
    ▼
④ 执行并验证业务结果 → 进入阶段④复核
    │
    ▼
⑤ 全无可用能力 → 退回「知识指引模式」
    ├─ 提供方法、模板、公式与检查清单
    ├─ 明确说明未实际处理数据、未生成文件或未完成外部操作
    └─ 说明缺失的能力、未完成范围及可由用户自行完成的步骤
```

禁止向未知第三方传输财税数据。工具返回成功只代表技术调用完成，不代表业务任务完成。

### 文档解析能力（document.extract）的授权与脱敏

当任务需要解析文档（PDF、图片、扫描件、DOCX、PPTX、XLSX、网页等 → 结构化文本/表格）时，走 `document.extract` 能力发现，实现可能是宿主原生能力、宿主已配置的 MCP（如 MinerU MCP Server）或本机 CLI（如 mineru CLI）。

授权与数据安全规则：

```
① 优先选择本地 / 离线实现
    └─ 若宿主或本机具备离线文档解析能力（如本地部署的 MinerU）→ 优先使用，不外传
② 需要将文件上传到外部 / 云端服务解析（如 mineru.net 云 API）时
    ├─ 先向用户说明该操作会上传文件到外部服务
    ├─ 财税文件含敏感信息时，建议先脱敏或征得同意再上传
    └─ 用户不同意 → 退回知识指引或改用本地实现，不擅自上传
③ 结果与材料落位（遵循 `operations/private_resources_rules.md`）
    ├─ 未配置 Mind 或用户未要求本地持久化 → 不复制原始材料、不写 Mind，并明确“本次不留存”
    ├─ 用户要求留存且 Mind 已配置 → 原始材料可进入 gridman-mind/02_input/
    ├─ CLI 直接结果 → 先进入 gridman-tools/outputs/，等待业务复核
    ├─ 任务需短期续用且 Mind 已配置 → 中间材料可进入 gridman-mind/03_temp/，任务结束清理
    └─ 阶段④复核后确需归档且 Mind 已配置 → 正式交付物进入 gridman-mind/04_outputs/
```

古立特不绑定任何具体解析工具，也不负责指导安装；MinerU 等仅为 `document.extract` 的一种可选实现示例。

### 工作流执行（多步骤任务）

如果任务需要多步骤执行（如审计底稿、IPO 尽调）：

```
① routing_index.md 的 L-1/L0/L1 命中 → 定位一个或多个专业领域
    │
    ▼
② 在命中的 knowledge 子树内实时列出文件并排序候选
    ├─ 优先依据文件名、文件头/frontmatter、适用场景与触发条件
    ├─ 缺少元数据时依据首个标题和前置说明
    └─ 只读取最相关候选；大文件再按标题 grep-first 定位章节
    │
    ▼
③ 需要多步骤执行时，在对应职业 Workflow 子树内使用同样的受限发现
    ├─ 存在且任务、输入条件匹配 → 由 Workflow 声明前置输入、能力需求、风险、步骤和专属验收
    └─ 子树不存在或无匹配文件 → 由 knowledge + 本文件通用流程组织步骤，不声称使用了 Workflow
    │
    ▼
④ 每步发现并选择宿主原生能力 / 宿主 MCP / CLI
    ├─ 有合适能力 → 执行并验证本步结果
    └─ 无关键能力 → 要求补充材料、手动完成或退回知识指引模式
    │
    ▼
⑤ 有 Workflow 时执行专属验收；无 Workflow 时执行通用验收；两者均通过阶段④复核总闸
    │
    ▼
⑥ 仅当用户要求留存、Mind 已配置且产出已复核时，归档到 gridman-mind/04_outputs/
```

发现边界：不得扫描整个 `references/`，不得因新增单个文件要求修改集中式路由；只有领域入口、硬闸或经真实误路由聚类证实的强锚才进入 `operations/routing_index.md`。

### 错误处理

执行报错时：
1. 分析原因（格式、路径、连接、参数、权限或能力不匹配）；
2. 仅在安全且不会造成重复写入时自动修复，最多重试 3 次；
3. 涉及外部写入的重试先确认是否已部分成功，避免重复提交；
4. 仍失败 → 告知具体原因、已完成范围和建议；仅当 Mind 已配置、错误真实且值得跨会话留存时，才写入 `05_learning/error_log.md`。


## 四、复核总闸（阶段④交付前）

任何"要交付的判断/结论/产出"给出前先过复核总闸。

### 复核类型选择（不每次全跑）

| 产出类型 | 复核维度 |
|---|---|
| 有数/有引用 | 维度A：四维自检 |
| 重大判断 | 维度A + 维度B：多视角复核 |
| 乐观结论（"未发现异常"） | 维度A + 维度B + 维度C：对抗者视角 |
| 简单知识问答 | 不触发复核 |

### 维度A：四维自检

| 检查项 | 内容 | 不通过时的处理 |
|---|---|---|
| ① 勾稽 | 合计、勾稽、平衡是否核对通过 | 差异先自修，自修不了红字标出，绝不假装对上 |
| ② 依据正确 | 准则/税率/标准是否现行有效 | 标出待核实项 |
| ③ 口径一致 | 指标/单位/时间/来源全篇一义 | 修正后重检 |
| ④ 引用核实 | 文号/数字已查或标"待核实" | 标出未核实项，绝不编造 |

全部通过 → 盖 ✅ 已四维自检
有未决项 → 红字带交付
自错 → 追到 `05_learning/gotchas.md`

### 维度B：多视角复核

对立利益立场各审：
- 税局 vs 企业
- 买方 vs 卖方
- 监管 vs 被监管

一致 → 一句确认
不一致 → 指分歧点 + 各自依据 + 提示补什么 / 谁拍板（不替裁决）

### 维度C：对抗者视角（审计/反舞弊立场）

假想"如果我要造假，从哪下手"，回头反查：
- 配 `references/knowledge/analysis/financial_fraud.md` + Red Flags
- 立场锁死：只预判造假以识破，绝不下场造假 / 编假数据


## 五、统一交付模板

### 按交付类型套用

| 交付类型 | 模板 |
|---|---|
| 知识问答类 | 结论（一句话）→ 依据（准则/条款/口径）→ 边界与例外 → 下一步 |
| 工具产出类 | 原始结果摘要 → 财税判断 → 风险点 → 附模板/填空位 → 来源标注 |
| 重大判断类 | 双方依据并列 → 分歧点 → 风险点 → 谁拍板 → 建议核实路径 |
| 涉税/法规类 | 结论 → 时效标签（"以最新官方为准"）→ 核实闸门 |

通用原则：结论先行；数据注出处。

### 交付前必勾

- [ ] 四维自检通过
- [ ] 重大判断已过对立视角
- [ ] 乐观结论已过对抗者视角
- [ ] 来源已标注


## 六、路由执行完整闭环

```
用户问题
    │
    ▼
阶段②：路由判断
    ├─ 轻量场景 → 直接答 → 结束
    ├─ 纯知识问答 → routing_index.md（知识路由）→ 读 references/knowledge/ → 阶段④复核 → 交付
    └─ 需外部操作/数据 → 阶段③执行
    │
    ▼
阶段③：执行
    ├─ 宿主原生能力可用 → 执行 → 阶段④
    ├─ 宿主 MCP 或本机 CLI 可用 → 执行 → 阶段④
    └─ 全无 → 退回「知识指引模式」→ 结束
    │
    ▼
阶段④：复核 + 交付
    ├─ 复核总闸通过 → 交付
    ├─ 有未决项 → 红字标出后交付
    └─ 自错 → 修正后交付；仅在 Mind 已配置且值得跨会话留存时记入 05_learning/gotchas.md
```
